# S6 原生提交入口原型：观察与原样透传

这是独立的开发测试插件，不是 PenChat 显示后端，也不是已完成的合成器。
生产构建不引用此测试目录；不修改应用版本、AppID、业务页面或现有 CVI 显示路径。

## 本轮验证的内容

在 S6 的 Falcon 原生 `greenui::post_fb(void*, const Rect&, int, int)`
调用槽处安装一个可撤回观察器。观察器可以限量复制提交前的完整画面到普通内存，
随后恰好调用一次原函数，所有参数（包括原始像素指针和 Rect 引用）保持不变。
诊断副本不提交显示，不改变旋转、区域、翻页或垂直同步。

- 仅支持已核验的 CV1826 / Plum S6。
- 固件门禁使用实际 `/usr/lib/libfalcon.so` 的完整 SHA-256：
  `11e46687d3c7301d3049d02d84144ee37e5a9994ca5ec1e9f5eaf278db92519b`。
- 动态解析 ELF 的 PLT 重定位，只接受唯一、已经解析、仍由原函数占有的槽。
  不使用固定内存地址、指令覆写、ptrace 注入、驱动解绑或设备节点替换。
- 仅原子交换调用槽；RELRO 页临时加写后恢复原保护，不修改磁盘系统库。
  原子比较防止覆盖其他接入方。
- 从 Falcon 配置读取逻辑几何；本机物理旋转下交换宽高，不使用环境中的错误几何。
- 最多30个设备样本、一个16MiB以内且与配置匹配的临时像素缓冲；不写图片或正文。
  状态输出只包含几何、次数、耗时、错误及恢复状态。
- 15秒原生看门狗自动撤回；页面隐藏、退出或手动撤回均停止观察并恢复原调用槽。
  调用期间不分配新的像素缓冲、不等待状态查询、不写日志文件。
- 停止后清零并释放像素副本。为保护可能已经取得旧调用槽值的在途线程，
  小型中继代码和状态保留至宿主进程自然结束，不主动卸载。不会重启宿主来回收它。

上述门禁限定本次已知固件，不能据此声称兼容其他 S6 固件或其他机型。

## 主机测试

```sh
cmake -S tests/device/falcon_submit_probe -B build/submit-probe-host -DCMAKE_BUILD_TYPE=Release
cmake --build build/submit-probe-host -j4
ctest --test-dir build/submit-probe-host --output-on-failure
```

真实 ELF 测试库使用 NOW/RELRO，覆盖完整性门禁拒绝、参数及源像素保持、
单次透传、样本上限、无效诊断仍透传、原生定时撤回、重复停止、异主槽拒绝，
以及4个并发调用线程共12,000次调用期间的撤回。
可用相同 CMake 项目单独执行 ASAN/UBSan；不需要运行应用全套回归。

## ARM32 与独立 AMR

```sh
python3 tests/device/falcon_submit_probe/package.py
```

构建使用 `scripts/native-target.sh cv1826-s`，自动生成独立16位测试 AppID，
保存在忽略的 `build/submit-probe-package/identity.json`。生成的 AMR 只包含
测试页和原生测试插件，不打包 PenChat、CVI 显示/扫描代码、模型或用户数据。
插件还校验当前 AppID，不能放入正式应用直接启用。
设备依赖其已有的 `libcrypto.so.1.1`，仅用于门禁文件的 SHA-256。

安装前检查目标设备和 AppID 冲突，仅可操作 S6 `JDA0700006552216`。
先在独立进程运行 `submit_probe_tests` 和 ARM32 fixture，再启动 AMR。
测试页自动进行约3.5秒纯透传和约4.5秒读取观察；每次原生接入仍受15秒上限保护。
按钮允许重跑、立即撤回和退出；页面隐藏会撤回，返回不会偷偷重新接入。
运行结束的两份纯统计 JSON 保存在测试应用自己的 data 目录，不能借用 PenChat 数据。
测试程序不自动部署、重启宿主或操作其他设备。

截图、完整原文、研究文件和安装包保留在忽略目录，不入 Git。
15秒看门狗的到期路径在主机与S6独立进程中验证；本轮真实Falcon页面主动停止

S6正式应用现在也复用该实现。下文第1/2步的记录描述当时原型边界，正式接入的
最新结果见 `docs/S6-ARMV7-DEV.md` 与 `native/compositor/README.md`。

## 第2步：独立进程中的 LVGL 与共享内存合成

同一个独立测试包新增 `composite` 页面。使用 `miniapp_cli start <测试AppID> composite`
进入；本机 CLI 的第三个参数是页面名，不要给页面名加 `--`。

链路如下：

```text
Falcon post_fb 原始帧
  -> 两个只读消费的共享系统帧槽
  -> 独立 ARM32 测试进程（真实 LVGL 示例 + 原生 BGRA 合成）
  -> 两个共享输出槽
  -> Falcon 内的串行适配器 -> 原 post_fb -> 原 cvifb
```

当前是一个测试生产者：LVGL示例与合成计算在同一独立进程。
尚未将正式PenChat进程或浏览器作为外部生产者注册到通用多客户端服务。
不修改正式DisplaySurface，不复制聊天/键盘业务，也不接管fb0驱动。
原生测试进程不加载Falcon/CVI库、不打开fb0或video109；进程启动使用posix_spawn，
不执行shell。真实设备的子进程FD检查仅有stdio、IPC、memfd以及前台只读evdev。

### 所有权、焦点与退出

- 使用带GROW/SHRINK/SEAL限制的memfd，两个系统槽、两个输出槽。消息为固定40字节
  的本地SEQPACKET协议，包含版本、序号、槽号与焦点代次；不通过JSON/JS传递像素。
- 生产者提交后不能重写槽，接收方完成消费后回复释放通知。系统侧过载最多保留一份
  最新待提交副本；队列、映射、包长度和索引均有界，非法消息停止本次租约。
- 系统源只在变化时复制；没有新系统帧时，LVGL仍可独立刷新。子进程使用预乘BGRA
  合成，保留透明度；透明和不透明区域有原生NEON快路。
- 只有Falcon内适配器调用原提交函数，异步输出与直接系统回退共用串行锁。
  启动等待首个系统提交，退出先排空输出，再恢复调用槽并释放共享内存。
- 复用应用现有NativeTouch和Screen解析。触摸只由evdev读取，不经过Falcon坐标转发。
  系统页头/底部控件不进入示例控件命中；多点或取消会终止该次示例触摸。
- 复用`$am.hasWindowFocus`及窗口事件；焦点代次阻止旧合成帧回写。
  焦点丢失关闭触摸设备；300ms未收到焦点心跳也停止原生触摸/画面。
- 原生租约为25秒；手动停止、后台、断开、异常子进程退出或期限到达均回到系统路径。
  临时像素与子进程退出，不卸载仍可能被在途调用引用的中继代码。
- 新模式和第1步观察器互斥，仍使用完全相同的固件哈希/ELF门禁。
  模式几何不匹配时停止原型并透传，不重新解释图像尺寸。

### 定向验证结果（2026-11-08）

主机普通测试、核心ASAN/UBSan和S6实际ARM32独立进程测试覆盖：
memfd不可缩放、包大小/格式、非8倍数宽度及不同Alpha逐像素对照、持续独立输出、
焦点关闭/恢复、心跳过期、异常输出索引、断连、租约到期和原调用槽恢复。
实际S6通过原生触摸点击LVGL按钮；物理framebuffer截图同时呈现系统控件与LVGL。
Falcon自身截图只含系统层与透明洞，不能拿它代替最终合成图验收。

| 实测项目 | 结果 |
|---|---|
| 第一轮完整租约 | 25.057s，系统2帧、LVGL706帧、实际输出703帧 |
| 当前代码完整租约 | 25.084s，系统1帧、LVGL714帧、实际输出714帧，约28.5fps |
| 合成中位耗时 | 约1.0ms/帧；本示例以透明/不透明区域为主，不等于整帧半透明基准 |
| 系统帧交接 | 起步1～2帧约2.2～2.5ms，包含首次共享页触页/分配和交接，不是稳定拷贝基准 |
| 原提交函数中位耗时 | 完整轮约11.4ms，含旋转/复制及垂直同步等待，并非纯CPU时间 |
| 共享映射 | 2670592字节；另有一份最新系统待提交副本和LVGL CPU画面 |
| 5.2s CPU采样 | 子进程约7.9%，整个Falcon宿主约7.1%，S6一个在线CPU核 |
| 子进程内存采样 | RSS4712KiB、PSS2814KiB、Swap0；共享页已计入PSS，不能重复相加 |
| 同页停用后宿主采样 | 约3.5% CPU；非严格成对压力测量，不将整宿主占用归因于原型 |

实际故障/生命周期检查：手动停止、正常IPC断开、进入系统页面、SIGKILL指定测试
子进程以及25秒到期，均恢复原函数，无残留子进程/共享映射。系统控制中心覆盖时
实际关闭evdev；手动收起后，新一轮可重新打开并操作。覆盖测试期间超过25秒租约，
因此不声称该次为“同一子进程跨长时间控制中心覆盖后恢复”。focus false/true和
心跳过期状态机另有主机及ARM32进程测试。宿主PID、boot ID保持不变。

本机GCC12 sanitizer + PIE存在独立于项目的随机启动段错误：空程序8/40次失败，
非PIE空程序40/40次正常。仅sanitizer测试可执行文件使用`-no-pie`，DSO仍为PIC；
ASAN/UBSan插桩保留，原始SIGSEGV仍失败，关闭递归SIGSEGV报告以避免运行时日志风暴。
修正测试启动配置后两个核心测试连续三轮通过；设备和生产构建不采用该配置。

完整日志、截图、原始采样和AMR留在忽略目录。原型结束后卸载独立测试应用并清理
设备临时文件，不更新正式PenChat，不更改扫描实现，不重启宿主、不操作其他设备。
多版本开发插件为保障在途调用会保留到宿主自然退出，不能将它们算作完全卸载。
