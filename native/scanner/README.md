## 数据流

聊天页前台、没有菜单/弹窗/输入法时准备硬件；准备完成才响应新的笔头按下。
系统采集服务刚恢复时先在准备态等待CaptureFrame出现，再保存租约、暂停守护进程，
等待旧采集进程实际退出后才申请V4L2缓冲，避免快速重扫时与旧所有者竞争。
进入时笔头已按住则等待释放；左侧显示准备/就绪状态，不可用时可点击该状态重试。按下后立即请求白灯并接纳原始 NV12 Y 帧，采集不等待
模型加载、首批凑满或页面重绘。

- CPU连续选帧；选中帧立即生成80×144模型图并估计亮度系数。
- 固定32帧、步长24、重叠8；后续推理与上一批绘图允许重叠。
- 原分辨率光照校正在绘图时应用，保持原数值行为；模型输入不改成校正图。
- 已提交且不再引用的帧及时释放；保留8帧衔接及累计画布。
- 软容量停止时停止新增曝光，最多交回16张在途帧后封口；笔头松开也封口。
- 帧池48MiB、画布32MiB、自管预算96MiB、240/256帧水位、RSS软水位240MiB。
  这些数值不是RKNN内部全部分配；256MiB RSS及整机余量仍需实测。
- 首版只保留一笔采集或一个待确认结果；模型空闲5秒释放。

完整、部分和空扫描全部先进入结果页。完整结果可“使用图片”；不完整结果明确显示
停止原因和未定位帧数，按钮为“仅使用已拼接部分”；空结果禁用使用。确认前不建消息、
不保存空会话。确认后原图/缩略图一同提交，之后才按现有自动发送开关处理。

结果默认保留灰度原图，不裁剪或偷偷缩放发送。输出按行PNG编码，单个文件限制16MiB，
失败删除未完成文件。仅确认时保存最终PNG和缩略图，不保存逐帧图片或磁盘队列。
聊天、历史和相册使用数据库现有 display_src 缩略图；模型请求使用完整 stored_path。
扫描状态、计数、校准版本及时间点使用现有 metadata_json，不迁移数据库结构。

## 进程和硬件所有权

penchat-lvgl 与独立 penchat-scanner 使用版本1 Unix seqpacket 通信；
请求和结果包含 requestId、generation、session、scanId。预览使用一个共享memfd槽，
最多1024×256灰度像素，每100ms至多发布一次；序列号保护读取快照，不在socket排队大图。
画布bounds/readPreview在独立后台读取，采集循环只获取最新已完成的小图，不等待画布锁；
普通请求在读取忙碌时合并，终态仅保留一个最终请求，取消先排空读取再释放结果。
UI更新只在主线程；扫描进程不继承AMR、DRM、数据库或网络描述符，也不继承预加载钩子。

ORANGE配置为 sc2356、/dev/video23、/dev/v4l-subdev2、496×360 NV12，以及
/dev/input/by-path/led_control 的134号键。白灯直接控制GPIO43，不逐次启动shell，
不改动红外灯GPIO44。源序号断裂会停止本笔并标为部分结果，不能静默计作完整。

接管前，扫描进程先把系统扫描守护进程的PID、启动时间、暂停状态快照交给父进程；
父进程确认保留恢复信息后，子进程才接管。只接受可恢复且未被其他调用方暂停的
系统扫描服务。正常撤销时关灯、关闭quick-stream、释放V4L2和按键，再恢复守护进程。
子进程异常时父进程补做恢复；若守护进程已经恢复运行，不再触碰新启动的CaptureFrame。
不停止或重启系统MiniApp宿主。

父子进程共享一个flock打开文件描述符；锁保持到子进程退出、父进程完成补救恢复之后，
避免快速重进时旧清理误伤新扫描。运行期只多一个空的 /tmp/penchat-scanner-<AppID>.lock
控制文件，不包含图像或队列数据。正常撤销不再在旧灯线程析构时重复写GPIO。
取消/断连先恢复硬件，再给剩余NPU清理设置3秒退出边界；正常松手的结果处理不受此边界限制。

菜单、输入法、拍照、相册、API Key OCR、后台及Home撤销扫描占用；
收到硬件释放确认后回收空闲子进程，返回聊天再重新准备。系统输入法、
系统OCR和拍照实际启动须等待撤销完成。后台/离页取消本笔，迟到结果不能写到别的会话。
丢弃/退出会清理待确认文件；已确认资源由业务数据库持有。

## 依赖与构建

engine 中保存必要生产源码、契约测试及公开RKNN头文件；源码、模型、冻结光照表、
板端OpenCV 3.4.3及私有运行库的指纹在 dependencies.lock.json。PNG固定1.6.37，
同时锁定SDK中的源码指纹并保留许可。模型和共享库在生成的 assets/scanner，保持Git忽略。
ONNX、历史数据、研究工具链和旧拼接库不进入仓库/生产包。

默认资源包：

    /home/ls-jl/Documents/ChatGPT/词典笔扫描拼接/deliverables/stream32_complete_20261018

可用 PENCHAT_SCAN_BUNDLE 指定资源包，PENCHAT_SCAN_CROSS_ROOT 指定现有GCC12交叉环境，
PENCHAT_SCAN_BOARD_LIBS 指定与锁定指纹一致的板端依赖。默认C++17编译器包装使用GCC12
语言头文件、板端glibc 2.17头文件和正常GCC6 CRT链接，避免诊断程序的自定义_start。
也可通过 PENCHAT_SCAN_TOOLCHAIN_FILE 提供兼容板端ABI的标准CMake工具链。
LVGL仍使用原有工具链；现代libstdc++只在扫描子进程的私有库目录使用。

构建和回归命令（不会由应用自动运行）：

~~~bash
npm run build:host
npm test
npm run test:sanitize
npm run build:native
npm run build:prod
npm run check
npm run check:package
~~~

构建与测试分开：build:scanner:host只构建；test:scanner运行核心契约、PNG上限、
真实扫描子进程协议和LVGL双进程集成。主机模拟入口仅存在于主机测试构建，不进入AArch64。
ASAN/UBSan可使用SCANNER_SANITIZE=ON；两个进程测试支持PENCHAT_SCANNER_TEST_BINARY，
LVGL测试同时支持PENCHAT_TEST_BINARY及PENCHAT_TEST_TIMEOUT。
ASAN使用小隔离区 `quarantine_size_mb=8:thread_local_quarantine_size_kb=64`，
避免测试分配器自身触发引擎240MiB RSS水位；不提高生产限额。主机ASAN可执行程序
用 `-no-pie` 链接，避免当前主机PIE与ASAN组合的随机启动失败（DEADLYSIGNAL）。应用泄漏检查仅通过
`LSAN_OPTIONS=suppressions=.../tests/lsan.supp` 排除MicroTeX启动符号注册中既有的
12字节重复项；不关闭扫描器或其他应用分配的泄漏检查。

## 统一验收范围（完成证据见 docs/LVGL-ACCEPTANCE.md）

- 全部尾批和0/1/31/32/33/56/57/80帧边界，慢NPU、画布不足、错误保留及连续任务。
- 逐行PNG无损、16MiB失败清理；确认前零消息、重复确认仅一次、丢弃、旧会话结果排除，
  原图/缩略图保存和回读，自动发送开关及生成中的扫描。
- 正向中文/英文、快慢、不同光照及困难样本的文字质量审阅；反向不纳入首版支持。
- 实际采集与NPU同时运行时的帧序号、吞吐、RSS和整机内存；无中间帧文件。
- ORANGE真实按键、输入法/OCR、拍照/相册、菜单、Home/后台及异常退出，连续20次恢复，
  确认灯灭、按键和相机无遗留、系统扫描恢复、MiniApp宿主PID不变。
- 新扫描页截图回归；保留既有Markdown/数学基线。最终AMR核对原生架构、资源指纹、
  私有库白名单及不包含测试入口/回放程序。

tests/device/scanner_probe.cpp 是独立硬件探针，不访问业务数据库；应先关闭PenChat原生进程，
避免与应用持有的扫描进程锁冲突。
需要NPU数值回放时，以 PENCHAT_SCAN_REPLAY=ON 构建非生产 scanner-replay，再显式运行
tests/device/scanner_replay.py（主机需Pillow和NumPy），传入资源包内的原始帧目录和对应期望图/掩码。输入与结果留在
主机，设备端只有唯一临时目录中的模型、运行库、程序及PID控制文件；回放工具不进入AMR。

`tests/device/scanner_acceptance.py` 使用真实触摸检查20次菜单/输入法/相机/相册/Home、
系统OCR及扫描子进程异常恢复；`tests/device/scanner_capture.py` 使用配对笔头事件检查
20次真实传感器采集、计数、亮灯请求时间和丢弃。二者只面向指定ORANGE，不创建消息。
这些硬件检查与纸面质量验收分开；不能把全部帧入画当作文字质量通过。
