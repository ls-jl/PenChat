## 数据流

聊天页前台、没有菜单/弹窗/输入法时准备硬件；准备完成才响应新的笔头按下。
系统采集服务刚恢复时先在准备态等待CaptureFrame出现，再保存租约、暂停守护进程，
等待旧采集进程实际退出后才申请V4L2缓冲，避免快速重扫时与旧所有者竞争。
进入时笔头已按住则等待释放；左侧显示准备/就绪状态，不可用时可点击该状态重试。按下后立即请求白灯并接纳原始 NV12 Y 帧，采集不等待
模型加载、首批凑满或页面重绘。

- CPU连续选帧；选中帧立即生成80×144模型图并估计亮度系数。
- 固定32帧、步长24、重叠8；后续推理与上一批绘图允许重叠。
- 原分辨率光照校正在绘图时应用，保持原数值行为；模型输入不改成校正图。
- 已提交且不再引用的帧及时释放；保留8帧衔接及累计画布。
- 软容量停止时停止新增曝光，最多交回16张在途帧后封口；笔头松开也封口。
- 帧池48MiB、画布32MiB、自管预算96MiB、240/256帧水位、RSS软水位240MiB。
  这些数值不是RKNN内部全部分配；256MiB RSS及整机余量仍需实测。
- 首版只保留一笔采集或一个待确认结果；模型空闲5秒释放。

完整、部分和空扫描全部先进入结果页。完整结果可“使用图片”；不完整结果明确显示
停止原因和未定位帧数，按钮为“仅使用已拼接部分”；空结果禁用使用。确认前不建消息、
不保存空会话。确认后原图/缩略图一同提交，之后才按现有自动发送开关处理。

结果默认保留灰度原图，不裁剪或偷偷缩放发送。输出按行PNG编码，单个文件限制16MiB，
失败删除未完成文件。仅确认时保存最终PNG和缩略图，不保存逐帧图片或磁盘队列。
聊天、历史和相册使用数据库现有 display_src 缩略图；模型请求使用完整 stored_path。
扫描状态、计数、校准版本及时间点使用现有 metadata_json，不迁移数据库结构。

## 进程和硬件所有权

penchat-lvgl 与独立 penchat-scanner 使用版本1 Unix seqpacket 通信；
请求和结果包含 requestId、generation、session、scanId。预览使用一个共享memfd槽，
最多1024×256灰度像素，每100ms至多发布一次；序列号保护读取快照，不在socket排队大图。
画布bounds/readPreview在独立后台读取，采集循环只获取最新已完成的小图，不等待画布锁；
普通请求在读取忙碌时合并，终态仅保留一个最终请求，取消先排空读取再释放结果。
UI更新只在主线程；扫描进程不继承AMR、DRM、数据库或网络描述符，也不继承预加载钩子。

ORANGE配置为 sc2356、/dev/video23、/dev/v4l-subdev2、496×360 NV12，以及
/dev/input/by-path/led_control 的134号键。白灯直接控制GPIO43，不逐次启动shell，
不改动红外灯GPIO44。源序号断裂会停止本笔并标为部分结果，不能静默计作完整。

接管前，扫描进程先把系统扫描守护进程的PID、启动时间、暂停状态快照交给父进程；
父进程确认保留恢复信息后，子进程才接管。只接受可恢复且未被其他调用方暂停的
系统扫描服务。正常撤销时关灯、关闭quick-stream、释放V4L2和按键，再恢复守护进程。
子进程异常时父进程补做恢复；若守护进程已经恢复运行，不再触碰新启动的CaptureFrame。
不停止或重启系统MiniApp宿主。

父子进程共享一个flock打开文件描述符；锁保持到子进程退出、父进程完成补救恢复之后，
避免快速重进时旧清理误伤新扫描。运行期只多一个空的 /tmp/penchat-scanner-<AppID>.lock
控制文件，不包含图像或队列数据。正常撤销不再在旧灯线程析构时重复写GPIO。
取消/断连先恢复硬件，再给剩余NPU清理设置3秒退出边界；正常松手的结果处理不受此边界限制。

菜单、输入法、拍照、相册、API Key OCR、后台及Home撤销扫描占用；
收到硬件释放确认后保留子进程及健康的NPU模型，返回聊天时仅重新申请硬件。系统输入法、
系统OCR和拍照实际启动须等待撤销完成。后台/离页取消本笔，迟到结果不能写到别的会话。
丢弃/退出会清理待确认文件；已确认资源由业务数据库持有。

### 常驻及空结果重扫（0.2.19）

应用首次需要扫描时启动一个工作进程；普通切页、键盘/OCR、相册、后台和扫描结果
取消均复用该进程。生产引擎设置`idleModelMs=0`，表示取消原有5秒空闲模型卸载，
健康模型一直保留到应用退出；故障上下文仍按原有错误恢复规则关闭。
未占硬件时，子进程阻塞等待IPC，父进程使用可被命令立即唤醒的等待，
仅每250ms检查空闲子进程状态。应用退出或桥接断开会等待/终止子进程并做租约补救。

无可用图像的结果页不要求先取消。松开后再次按下笔头，先取消并排空旧预览，
释放空结果及本笔队列，再直接开始新扫描；不关闭采集硬件或重建NPU引擎。
若按下时旧结果还在处理，仅在最终确认为空且笔头仍按着时衔接新扫描；
已经松手则不延迟启动。重复按下事件不重复创建任务，有图的结果始终保留人工确认。
正常结果页取消/确认后返回聊天也只丢弃本笔结果；只有离开可扫描区域或硬件
已经故障释放时才重新交接采集设备。诊断包含worker_pid和hardware_armed供验收。

## Y02 原图采集适配（0.2.18）

- 仅启用已识别的 RK3562 Y02 + SC035GS 组合；ORANGE + SC2356 保持原有配置，未知板型、交叉匹配或缺失传感器均拒绝接管。屏幕尺寸不参与扫描硬件判断。
- Y02系统默认288×192，传感器原生640×480 Y8；ISP支持640×480 NV12。使用完整Y平面进入既有32/24/8拼接，按原始像素输出PNG，不先缩成ORANGE尺寸，也不使用系统OCR文字冒充原图。
- Y02在用内核与本地SDK的SC035GS实现不完全一致：内核日志明确显示quick-only等待，单独STREAMON实测不出帧。设置quick-only并启动V4L2接收端后，只发一次quick-stream；连续收到16个序号相邻的真实帧才报告就绪，2秒无稳定帧则报错并释放硬件。不重放SC2356的重复开流，也不在笔头松开时切断传感器；松开时按单调时间戳封口，窗口外帧不进入本次拼接。白灯仍为GPIO43，红外GPIO44不变。
- Y02固定平场明确标识为`y02-sc035gs-native-neutral-v1`，增益为1，逐帧光照估计仍运行。这不是工厂白纸校准，也不是ORANGE的历史补偿资源；纸面方向、均匀性与真实拼接质量需要实扫确认。
- 原始帧队列支持实际尺寸。保持64帧RAM入口、8帧预取和最多640帧，但Y02按110MiB磁盘上限收紧为375帧；仍为有序、无静默丢帧队列。较大图片不通过降低分辨率绕过预算。
- 租约保存原V4L2格式。正常退出及父进程补救都在恢复守护进程前还原；测试探针的白灯、640×480采集及恢复288×192不依赖重启MiniApp宿主。
- 主机使用独立Y02模拟入口验证完整帧尺寸、PNG确认/丢弃、匹配拒绝与队列上下限；模拟入口只编入主机测试，生产包不含该入口。

### Y07 SC2356 (0.2.25)

Y07 is an explicit board/sensor profile (752×440 NV12), not a Y02 fallback.
Its LED-class path is driver-owned; never export GPIO43 or unload that driver.
The capture guardian retains/restores LED brightness and the previous V4L2
format. Raw transport has been verified at 24 consecutive frames without gaps.
`calibration/y07-sc2356.json` is a separately locked **neutral**, not measured,
flat field. White-paper illumination, optical orientation and forward text
stitching still require physical validation before declaring Y07 scan acceptance.
The 110MiB spill bound yields 348 queued original-size grayscale frames at this sensor size.
