# 键盘 OCR 连续识别稳定性（dev）

2026-11-09，用户反馈 S6、Y07 均存在“有时插入、有时不插入”。本轮针对共用
代码与 Y07 两阶段交接修正，不改扫描算法、模型、数据库或 AMR 桥接版本。

## 代码中确认的风险路径

1. `scanWordResultChanged` / `apolloScanWordResultChanged` 先发空载荷时，旧代码
   立即结束本笔；之后到达的真实文字因 `started=false` 被忽略。
2. 完成/停止通知先到、文字属性后到时，旧900ms空结果等待结束就丢弃后续文字。
3. Y07 `ocr.prepare` 后同编号 `ocr.start` 会重建监听、清零划扫状态，并重复注册。
   交接窗口内已收到的开始或文字可能丢失。重复激活也会重新清零。
4. 原生300ms输入许可过期调用整套编辑中断，连仍处于1500ms采集许可内的 OCR
   一并注销。短暂负载抖动可能在识别途中撤销会话。
5. 部分启动失败回执缺会话、模式及终态信息，被原生过滤；同笔已插入后出现的
   终态路由错误，也被按重复文字丢弃。两者都可能留下虚假的“已启用”状态。

这些是代码中确认的丢弃/注销路径，不等于已经捕获用户每次不稳定的实机时序。

## 调整

- 空结果通知改为等待，最长2500ms；有实际完成内容沿用900ms等待最终文字信号。
  完成通知后文字属性再到时，120ms短合并后交付，不要求再来第二次完成信号。
  计时检查当前会话和划扫编号；没有真实开始信号时不启动计时、不报空扫。
- 同编号、编辑会话、模式和路由的 prepare→start 复用原监听与状态；重复激活
  不重复注册、不清零候选或划扫编号。切字段、模式变化及旧编号仍按原规则隔离。
- 输入许可短暂过期只取消触摸；采集许可仍有效时不停止 OCR。真正失焦、后台、
  官方键盘、关闭编辑器和采集许可失效仍注销。采集失效独立处理，不能依赖已经
  取消的触摸再次发生状态变化。
- 启动失败统一带 requestId/session/mode/terminal 回执，原生发送失败也退出
  虚假就绪状态。终态错误不受普通文字去重阻挡，已有输入保留并显示重试入口。
- 不记录识别文字、密钥或用户输入；不添加隐式扫描、自动模型请求或系统拼音借用。

补充迟到文字、空通知、预注册交接、重复激活、取消后旧计时、同笔终态失败和
输入/采集许可分离的回归用例源码。按用户约定，不执行自动主机/设备验收，
也不运行全套回归、ASAN或性能测试；只做必要语法/编译及开发包静态检查。
