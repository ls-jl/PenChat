# 聊天包格式 · 版本1

文件后缀为 .penchat.zip。它是标准 ZIP，使用 UTF-8 文件名。以下路径均相对 ZIP 根目录；不写入设备绝对路径。

## 目录与清单

```text
manifest.json
conversations/example.json
markdown/示例.md
assets/example.png
```

只有 manifest.json 必须在根目录。其他条目只允许位于 conversations/、markdown/、assets/；不要生成空目录条目、加密条目或符号链接。

manifest.json：

| 字段 | 类型 | 要求与含义 |
|---|---|---|
| format | string | 必填，固定 penchat |
| version | integer | 必填，固定 1 |
| kind | string | 必填，固定 chats |
| app_version | string | 可选，生成该文件的应用版本，不控制格式兼容 |
| items | array | 必填，1～2000个会话索引 |
| files | object | 必填，除manifest自身外的条目大小与校验值 |

items 的每个索引必须有 file 字符串，指向 conversations/ 下已在 files 声明的 JSON。title 和 markdown 用于说明与解压阅读；标准导出会同时生成 Markdown。

files 的键为包内路径，值为对象：size 是实际解压字节数；crc32 是该文件原始字节的 CRC32，8位小写十六进制字符串，左侧补零。ZIP 自带 CRC 也必须正确。除 manifest.json 外，不可含未在 files 声明的文件。

```json
{"format":"penchat","version":1,"kind":"chats","items":[{"file":"conversations/example.json","title":"示例","markdown":"markdown/示例.md"}],"files":{"conversations/example.json":{"size":123,"crc32":"0123abcd"}}}
```

上段只演示结构，size 与 crc32 是占位值，不能直接导入。需要可导入文件时使用资料包里的完整示例。

CRC32计算示例：

```python
from pathlib import Path
import zlib
raw = Path("conversations/example.json").read_bytes()
entry = {"size": len(raw), "crc32": f"{zlib.crc32(raw) & 0xffffffff:08x}"}
```

## 会话对象

| 字段 | 类型 | 要求与含义 |
|---|---|---|
| id | string | 来源标识；标准导出包含，导入后重建内部ID |
| title | string | 必填，UTF-8不超过1024字节 |
| status | string | 建议填写 active 或 archived；省略按active处理 |
| created_at、updated_at | integer | 必填，Unix毫秒时间 |
| last_message_at | integer | 可选，真实最后聊天时间；未知省略或0 |
| pinned_at | integer | 可选，置顶时间；0表示未置顶 |
| preview_text | string | 可选，摘要文字 |
| model、compression_model | object | 可选模型描述；空对象表示未指定 |
| metadata | object | 可选，配置、时间及压缩公开状态 |
| messages | array | 必填，1～100000条有序消息 |
| assets | array | 必填，无图片时使用空数组 |
| origin | object | 必填，source与checksum均为字符串 |

origin.source 标识来源会话，origin.checksum 标识这一版内容。标准导出用会话对象去掉origin后的紧凑JSON计算CRC32；它用于识别重复，不能验证身份。编辑内容后应更新checksum，避免被识别为同一份导入。

## 消息对象

| 字段 | 类型 | 要求与含义 |
|---|---|---|
| seq | integer | 必填，大于0，按数组顺序严格递增，可有间隔 |
| role | string | 必填，user、assistant 或 system |
| status | string | 必填，complete、cancelled、error 或 interrupted |
| message_type | string | 必填，使用 text 或 image |
| created_at、updated_at | integer | 必填，Unix毫秒时间 |
| text | string | 必填，原始Markdown；无正文用空字符串 |
| reasoning | string | 必填，可展示的思考/公开总结；没有则空字符串 |
| parts | array | 必填，按顺序列出文字和图片分段 |
| model | object | 可选，本消息请求使用的模型描述 |
| request | object | 可选，请求公开参数快照 |
| metadata | object | 可选，公开思考计时、用量及时间信息 |

文字分段为 {"type":"text","text":"内容"}，图片分段为 {"type":"image","asset":"asset-id"}。asset必须指向本会话assets中已声明且唯一的id。文字同时存在于text与文字分段时，请保持一致；导入以消息正文text为准。

消息request仅保留model、effort、effort_value、summary、system_prompt。metadata公开字段包括reasoning_observed、reasoning_duration_ms、reasoning_complete、reasoning_timing_source、imported_reference、usage、timeline。耗时单位毫秒，未知时省略，不伪造0。

timeline使用version=1，可包含sent_at、request_started_at、completed_at、last_activity_at，均为真实Unix毫秒时间。usage中的缺失计数保持未知，不代表0或实际账单。

## 图片资产

assets中每项使用下列字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| id | string | 会话内唯一标识，供parts引用 |
| file | string | assets/下的原图路径，需列入files清单 |
| preview_file | string | 可选缩略图路径；没有用空字符串 |
| width、height | integer | 像素宽高；未知可省略或0 |
| size_bytes | integer | 原图字节数；未知可省略或0 |
| mime_type | string | 可选，例如image/png |

正文内联图片可用 penchat-asset:资产ID 引用；导出Markdown使用 ../assets/原图文件名。原图、缩略图可以共用相同包内文件；重复文件只保存一次。

## 模型与会话配置

模型描述形如 {"provider":"示例服务商","endpoint":"https://example.invalid/v1","api":"responses","name":"example-model"}。非空描述中endpoint、api、name必须是字符串；provider为可选说明。api只能为responses、chat、anthropic。地址不得带用户名、密码、查询凭据或认证头。

导入仅在地址、接口类型、模型名称完全一致且本地唯一时绑定。未匹配可在预览中指定，或保留待配置；不会自动创建服务商。

metadata.chat_preferences可包含system_prompt、effort、gauge、preset_name、preset_adjusted。内部model_id和preset_id不作为跨设备关联传输；聊天模型与压缩模型分别使用顶层描述。

metadata.context_compression为可选摘要：version=1、through为覆盖末尾AI消息的seq、summary为非空文字，最多256KiB；created_at、revision为整数，enabled为布尔值，checksum为16位小写十六进制。标准导出会根据可移植消息与图片签名重新计算摘要校验；手工制作时建议省略此对象。校验不匹配或缺图会保留完整历史并停用摘要，不会丢弃原文。

摘要校验使用64位FNV-1a：按seq遍历覆盖范围，对紧凑UTF-8 JSON数组[seq,role,status,text,图片签名数组]的每个字节异或再乘1099511628211，按64位溢出；每条后额外处理字节255。初值14695981039346656037。每幅图片签名是[width,height,size_bytes]的紧凑JSON字符串；字段缺失时用null，显式填写0时按0参与，顺序与图片分段一致。

metadata.compression_archive只保留label和created_at。导入不保留原设备的内部归档ID。摘要、配置与模型匹配相关信息均可省略，最小示例不包含压缩状态。

## 导入边界与行为

- 总解压量最多512MiB、最多10000条文件记录；不允许绝对路径、反斜杠、空路径段、点号路径段、冒号、重复路径或超过240字节的包内路径。
- JSON文件合计不超过32MiB，嵌套最多64层、解析事件最多100万次。导出单会话正文与思考合计最多16MiB。
- 缺少会话文件或校验不符直接拒绝；缺少图片会列出，只有用户明确允许才导入可用内容。
- 导入创建新会话并重建关联；重复来源与校验值默认跳过，可主动另存副本。默认值和当前草稿不被替换。
- 不导出空白会话、草稿、待发送图片、数据库、诊断、密钥、认证头、签名或加密思考续传条目。
