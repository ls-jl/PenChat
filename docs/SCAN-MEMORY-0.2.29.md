# 0.2.29 全内存扫描

## 数据与兼容

采集回调将完整灰度像素复制一次到页内存，立即交回V4L2缓冲。筛选线程持续处理原帧，
不等待NPU；拒绝帧及时释放，选中帧保存原始像素、模型小图及亮度系数。NPU线程从选中队列
组建32帧窗口，后续补24帧、共享8帧重叠；推理及绘制共享同一原图所有权，最后一个引用释放时归还原帧页。
磁盘帧队列已删除，临时原帧不写盘。原分辨率、筛选、亮度估计、模型及RKNN配置保持一致。
模型健康时继续常驻；81MiB左右的模型设备映射未通过修改模型、量化或SDK参数压缩。

仅明确取消会丢弃尚未处理的任务。正常松开、资源停止必须排空已经接收的工作；绘制无法继续时
保留未定位原帧及明确的部分结果。首帧参考及空/单帧/尾批行为保持原算法。

## 内存与接口

删除固定240MiB RSS、48MiB帧页、32MiB画布及96MiB自管字节判停条件。
统一预算每100ms读取MemTotal/MemAvailable，保留max(32MiB,MemTotal/20)，采样和页分配/释放串行，
采样后新增分配使用同一份余量。有效样本超过1秒未更新即停止新增采集；资源不足和分配失败不自动重试。
RSS及Swap仅用于诊断，不作为固定进程总量上限。几何、尺寸及整数溢出校验继续有效。

扫描子进程启动时固定glibc的大块映射/堆收缩阈值为128KiB，避免模型加载后的动态阈值上升；
这只是分配策略，不是内存容量上限，不修改其他进程或RKNN设备缓冲。
原帧、模型小图、旋转/校正临时图和全尺寸增益图按页申请；每线程只保留必要工作区，收尾释放。
保留画布在收尾进行无损压缩；替换页申请失败仍保留原像素。处理静止后执行一次glibc空闲页回收，
取消/释放结果同样收尾，不每帧trim，不卸载健康模型。

内部新增SystemMemory、动态预算探针、明确的cancelScan、checkResources/reclaimIdle；
PushResult/BeginResult保留真实失败原因。模型SDK调用不变。没有数据库迁移或AMR桥接版本改变。
扫描结果增加raw/selected队列峰值、唯一帧页、画布、RSS/Swap、系统余量及memory_at_stop；
诊断仅取白名单数值。界面区分内存余量不足、状态不可读、申请失败及画布错误。

Y02用户实扫接收405帧、筛掉104帧、选中并提交301帧、13批，未定位0、未触发内存判停。

该次实扫存在7次真实源序号断档，共缺11帧，分别缺3、2、2、1、1、1、1帧；
有接缝错位，不能标为质量通过。丢失发生在筛选前，不是将过滤帧误计为丢帧。
独立诊断以只读方式观察驱动，并在原有硬件租约下采集：先约950帧无损，开始模型加载/推理负载后，
出现3次断档、共缺11帧，最大连续缺7帧。同期ISP输入计数出现跳变，输出无缓冲丢失计数为0、
仍有11～12个输出缓冲。另一次40秒/4752帧复测未丢帧，说明是间歇现象。
这些结果支持继续调查ISP读回/系统负载，但尚不能证明具体硬件损坏，或所有对齐错误都由丢帧造成。
