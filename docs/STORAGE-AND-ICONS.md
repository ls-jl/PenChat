# 0.1.21：数据库与界面图标

## 数据库版本与备份

首次打开旧数据库时升级 schema 1 → 2。升级前执行完整性、重复键和所有权检查；
冲突只报告类型与数量，不自动删记录、重排消息或替换关联。
SQLite backup API 创建同目录 `penchat.db.backup-v1`，权限为 0600，文件与目录
同步落盘后才开始迁移。已有备份不会覆盖，重试会产生带 `retry` 后缀的新备份。
表重建、置顶字段回填、索引、外键和版本号在一个事务内完成；中断后由 SQLite
恢复，下一次启动重新验证并迁移。未知版本拒绝升级。

新增 `chat_sessions.pinned_at`、持久化 `asset_gc` 回收队列；增加消息序号、
消息分段序号、同 Provider 模型名称的唯一约束，以及会话/消息/分段/资产/
流事件/模型所属 Provider 的外键。历史模型选择保持软引用，失效时仍可重新选择。
已有行的 ID、正文、配置、请求快照及图片关联不变。未切换 WAL 或降低同步级别。

恢复备份必须先停止应用，并保存升级后产生的新数据；不能仅安装旧包来回退
数据库版本。备份包含私密配置，不应提交 Git 或作为诊断附件分享。

## 保存与查询

- 仓储业务在单一工作线程完成，嵌套 SQL 不再逐条跨线程等待。
- 界面保留 100ms 流式刷新，持久化每 500ms 提交最新快照。终态立即排队，
  正常退出等待保存任务完成。500ms 是调度间隔，磁盘阻塞、断电或强杀仍可能
  造成未提交增量丢失，不承诺零丢失。
- 消息正文、思考、状态、错误、元数据和分段正文在同一事务更新。消息 ID、
  请求代次、快照版本保证终态不被旧流式内容覆盖，重试另起代次。
- 保存队列合并同一消息的未处理快照，有界保存任务槽位与失败快照；失败会提示
  “重试保存”。自动命名只在完整回复成功提交后启动。
- 流式重排复用 UI 当前页快照，不为了每次重绘读取数据库。图片复制在后台、
  数据库事务之前完成，保存成功后才释放扫描/裁剪临时结果。
- 历史/归档按 SQL 排序，每页 30 条，底层使用键集游标；消息以 `seq` 游标分页。
  保留现有上一页/下一页按钮。分页锚点每组最多 128 个，消息锚点最多 8 组；
  预编译语句缓存最多 64 条。模型目录和设置缓存随写入失效，回滚也清除缓存。
- 模型目录不携带 API Key 或请求头；发送及自动标题任务开始时读取 Provider 凭据。
  诊断只增加查询/事务/缓存数量，不增加正文、密钥或不透明思考内容日志。

## 图片回收

删除记录与登记回收路径在一个事务中完成，文件删除在提交后排队执行。
普通照片与扫描缩略图均覆盖；其他消息仍引用的资产会保留，最后一个引用删除后
再回收。只处理应用私有 assets 目录的直接文件，拒绝越界和符号链接，不改系统
相册原图。启动检查以批次运行，仅自动发现可确认由应用生成的孤儿文件，未知
文件保留；无所有者的资产记录也仅在明确带有本应用解除共享关联的标记时回收，
未知来源的独立资产记录保留。失败的删除保留队列记录供后续处理。

真机测试替换数据库前必须同时隔离 assets 和迁移备份，结束再恢复，避免测试库
把用户图片误判为孤儿。在线测试数据库通过 SQLite backup API 获取一致性快照，
不直接复制正在写入的数据库。`penchat-db-probe` 是测试工具，不进入 AMR。

## 界面

共享图标使用 24×24 设计坐标、2px 圆角线条和原生圆弧/圆角矩形，统一菜单、
返回、发送、回底、设置、相机、相册、新建、删除、置顶、推理强度与折叠箭头。
键盘 Shift、锁定 Shift、删除、Enter、左右光标同样使用原生绘制。
保持按钮位置、触摸面积、主题与应用启动图标。

历史长按菜单改为横向一行：重命名、置顶/取消置顶、归档、删除，按钮高 50px。
非空聊天内容顶部增加 8px 留白，第一条气泡不贴屏幕边缘；输入栏和上拉阈值不变。

## 验证入口

- `penchat-storage-tests`：1000 会话/100000 消息，迁移、异常中断、备份保留、
  游标分页、快照合并、失败重试、共享引用与孤儿/符号链接保护。
- `tests/test_storage_ui.py`：持有数据库写锁时仍能打开编辑器，并检查终态与两处正文一致。
- 原有完整主机回归、针对性 ASAN/UBSAN、离屏截图、AArch64 与生产 AMR 检查。
- ORANGE 使用临时测试配置验证两种 API、错误重试、取消、图片、历史操作与输入法；
  结束恢复用户数据，不重启 MiniApp 宿主。

主机一次合成基准：旧首页算法 10 次约 73ms，新 SQL 分页约 2ms；读取全部 1000 个
会话分页约 7ms；200 次快照提交约 1ms，合并为 2 次事务。存储测试进程峰值 RSS
约 10MiB，并非整个应用的内存占用。写锁阻塞测试中编辑器响应约 0.28s。结果受
机器负载影响，不作为 ORANGE 延迟承诺。产物位于 `.work/db-icons/`，不提交 Git。

最终 0.1.21 包在 ORANGE 完成 23 项聊天验收，包括两种 API、手动重试、取消、
拍照裁剪/相册、图片删除、拉动手势、推理及历史菜单操作。测试后逐表核对原有
业务记录完全一致，完整性与外键检查通过；图片目录恢复，系统宿主 PID 未改变。
主机完整回归、针对性 ASAN/UBSAN、交叉构建及 AMR 检查通过。`npm run check`
仅提示原有可选 cnpm 未安装。
