## CVI 反馈预览防护（主机通过，实机待连接）

用户确认没有操作 S6，且不在现场。USB 枚举和 ADB 均未发现 S6；同一集线器的
其他授权设备仍在线，端口 disable=0、over_current_count=0。主机账户无内核日志读取
权限，不能据此确认板端重启、供电故障或内核 panic；不把离线归为人为断开。
没有发出宿主重启或 USB 端口重置命令。

代码审查发现反馈预览会调用 feedbackHardware(true)，直接 open 所有 V4L2 节点，
再查询格式。历史 S6 ramoops 已记录过 cvi_isp_open / vb2_fop_release 失败清理 panic。
这是本次的重要怀疑路径，但新一次的内核日志尚未取得，不能宣称根因已实证。

防护使 CVI 反馈只读取 sysfs 节点名称与路径，视频节点标记 metadata_only/not_opened，
不再 open、ioctl 或 close 这些视频设备。RK 查询路径保持。新增测试使用临时普通文件
和 inotify，验证元信息路径没有 IN_OPEN，并用探测路径做阳性对照，不接触主机摄像头。
该测试及 15 项反馈回归通过；AArch64 和 S6 ARMv7/C++14 编译、完整包及无 shell 校验通过。
包保存在 `.work/s6-feedback-guard/packages/`，哈希见同目录上一层 identity.json。
S6 未安装这份防护包；必须先恢复原数据、读取可用的 pstore/启动日志，再进行隔离预览验收。

另有 SDK/固件目录约 260GiB；PenChat 本项目约 7GiB。只核对其他项目的目录/进程
