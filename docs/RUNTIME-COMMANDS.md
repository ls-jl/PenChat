# 运行时命令检查（0.2.6）

2026-10-26 检查原生应用、扫描进程、相机与加速度计、Falcon 启动桥接、
JS 启动页及原生测试。应用自有运行代码没有发现 `system`、`popen` 或
`sh -c` 调用；文件读写、目录遍历、硬件配置均使用原生接口。

## 清理内容

- 相机 `util.cpp` 留有无人调用的 `runCommand`，通过 `fork/execv` 启动任意
  参数指定的程序。它本来不经过 shell，但已没有运行入口；移除实现、声明和
  仅用于它的进程/信号头文件。
- 同时移除无人调用的 `findFfmpeg` 和声明；当前照片采集、像素转换、裁剪和
  保存使用 V4L2 与原生图像代码，不依赖外部 ffmpeg 命令。
- 历史时间、消息编辑、回复操作和拼音四个原生测试曾用
  `system("rm -rf …")` 清理临时目录。统一改成 `nftw`、`remove`，使用
  `FTW_DEPTH | FTW_PHYS`，不解释文件名、不跟随符号链接。
- 核心测试覆盖含引号、分号、美元符号和换行的文件名，以及指向另一个测试目录
  的符号链接；删除本目录后，外部目标文件仍然存在。

## 保留的原生子进程

| 位置 | 方法 | 用途 |
|---|---|---|
| `native/launcher/src/Launcher.cpp` | `fork` + `execl` | 启动随包的 `penchat-lvgl`，通过 socketpair 桥接 |
| `native/lvgl-app/src/scanner.cpp` | `fork` + `execve` | 启动随包的 `penchat-scanner`，保留独立扫描资源租约 |
| `native/camera/src/accelerometer.cpp` | `posix_spawn` | 启动随包的传感器守护程序，退出时恢复采样状态 |

这些调用直接提供可执行文件路径和参数数组，不使用命令字符串、shell 或 PATH
搜索。扫描算法、生命周期、守护进程退出恢复逻辑没有改变。
存储测试另有一个不执行其他程序的 `fork`，用于模拟数据库异常退出。

## 回归约束

- `tests/test_runtime_commands.py` 纳入 `npm test`：扫描自有原生源码与原生测试，
  禁止 shell 求值 API，限制子进程调用位置，并检查启动页不导入 shell/进程模块。
- `tests/runtime_policy.py` 读取 ELF 符号表；检查主机原生程序与桥接库，以及
  生产 AMR 内全部 ELF（含随包依赖）没有 `system/popen/wordexp` 等符号或
  shell 路径。AMR 不允许携带 `.sh/.bash` 脚本。
- 此检查针对项目源码和随包文件，不承诺系统提供的 Falcon、驱动及未随包分发的
  RKNN 运行库内部实现；未修改这些系统组件。
- `scripts/` 中的构建脚本、npm 构建入口和电脑端 ADB 验收工具继续使用各自的
  开发环境；它们不进入生产包，也不由应用执行。
