# PenChat 0.3.3 本地候选验收

用户要求完成全面技术检查并交付可发布候选包，版本指定为 0.3.3。
本轮不推送、不合并 main、不上传 GitHub 或在线更新目录；第三方再分发授权按用户
要求暂不评审，依赖身份、来源、完整性与许可说明文件仍保留检查。

## 范围与候选

从 dev 的 `0df96f2` 开始。包括控制中心资源常驻、RK 原生底层图层、CVI 共享合成、
横屏键盘 120ms 过渡、设置右侧过渡、Provider 自定义余额地址和扫描原图准备优化。
版本元数据在 `bf54978` 一次更新至 0.3.3。

本轮检查发现并修复：

- `a5b3202`：官方编辑结果未带 text 时，保留进入官方键盘前尚未确认的原始字母；
  明确返回空字符串仍表示用户清空。三种布局覆盖正常关闭与显式删除，不产生消息。
- `3dbb2c9`：MicroTeX 命令注册表在 main 前分配；数据库启动失败早于 RichText 构造，
  原先没有释放路径。源码覆盖层为注册表增加同翻译单元的退出清理，并使普通释放清空
  注册表，防止重复释放。数据库失败、再次启动与实际 IPC 失败恢复通过 sanitizer 复测。

后续实机截图发现第三项，已在 `3aa4d3d` 修复：640×260 的 100% 引导布局中，
“结束引导”与“上一步”重叠。窄文字工作区改用已有的自然宽度／必要时双行导航，
并使局部 reader 接收触摸，解决放大后原先只有滚动标记而不能实际拖动的问题。
新增 100% 和 640×260 组合、按钮矩形互不相交以及 150% 实际拖动断言。
主机七步完整流程覆盖四种 fixture；12 组布局／倍率和 ASan／UBSan／LSan 增量检查通过。
该修复已在最新两个架构的完整候选内；全矩阵与后续专项增量证据分开记录。

后续修复与构建保障：

- `f5a8308`：S6 实测普通前台偶发 302–349ms 的触摸心跳间隔，旧逻辑会同时清空键盘
  菜单、候选与查询状态。仍在 300ms 撤销触摸租约、关闭 fd 并取消触点，但独立媒体租约
  仍有效时保留编辑树和候选；真实后台或窗口失焦仍完整取消。恢复不重复查询、重建。
- `7384173`：传统全屏官方键盘正常收起可能先于确认回调，旧监视器误报打开失败并弹回
  内置键盘。仅在已有显示／页面往返证据时等待匹配 UUID 的确认；没有确认则正常关闭，
  保留原输入。真正未能显示仍报失败；Y07 内嵌实时编辑路径保持独立。
- `d2f58e9`：发现 RK 生产脚本此前只打包暂存二进制，候选 3、4 的 RK 原生部分仍是
  候选 2。已明确作废这些 RK 候选，保留原记录；生产构建现在先执行原生构建，并增加
  构建顺序回归。候选 5 显式交叉编译并将重新 strip 的输出与包内 ELF 逐字节比较。
  候选 6 只更新启动桥 JS，全部 13 个 RK、10 个 CVI ELF 与候选 5 逐个完全一致。

候选 1–6 的原包、身份和失败日志保留。源码覆盖层可重复生成，
不手工修改发布包或生成二进制。最终交付只使用候选 6。

## 检查与证据

完整主机检查拆成独立命令组，记录命令、二进制 SHA-256、测试源码身份、退出码与用时。
早期失败和重测分开保留。该记录是完整命令矩阵加最终改动的定向补验，
不宣称 173 条命令均在最终冻结后从头再跑一次。整棵测试树哈希包含独立设备脚本修改，
原始运行中的测试树变化标记也保留，见忽略目录内 `host-provenance-notes.json`。
旧测试将“官方键盘正常关闭”当作“恢复内置编辑”，
还会合成一次 Cancel 点击；现按正常关闭、显式失败、显式取消分别覆盖，避免额外点击
重新打开输入框。扫描完成等待稳定 prepared 状态，不依赖最后一个 IPC 包恰为 preview。

DRM 测试覆盖严格底层层级、Falcon 层级与 framebuffer 所有权；拒绝 zpos 后不回退为
上层覆盖。设备映射基础测试使用 reader 内的四点，系统顶边和返回边缘由专项测试覆盖。
截图后仅在仍拥有前台时等待正常输入租约续期，不伪造焦点、不穿过控制中心注入触摸。
自动触控补充确认：只有记录到短心跳安全取消、原生没有完整释放确认、业务／编辑状态未变、
实际内核触点已空时，才同步空释放并允许一次新的测试触点。迟到的完整释放不重按；
真实焦点丢失、面板出现、输入变化、发送／保存效果或活动内核触点均拒绝重按。
这些已取消的测试触点单独计数，不描述成设备从未丢失触控。19 项隔离工具单元检查通过。
快速地球切换专项先从实际三种布局解析按键中心，再用有界的三个物理触点一次发送；
记录每次实际按下时间，断言间隔小于 2 秒、原生接收三个触点、编辑版本增加三次且回到
正确布局。避免 S6 的逐次诊断读取超过 2 秒，将“快速循环”误测成普通中英切换。
失败记录与修正测试方法后的重新验收分开保存。

日志、截图、原始失败、设备隔离恢复凭据和完整包均在忽略目录
`.work/release-0.3.3/`。主机主矩阵在 `host-matrix/`，最终修复后的补验在
`host-final/`，sanitizer 在 `sanitizers/`，设备分轮记录在 `matrix/`。
最终有效结果需要合并原通过项、明确的失败重测与最终包增量验收，不能把旧失败覆盖为通过。

仅操作授权 Y01、Y02、Y07、S6。每个设备作用域隔离并恢复保存数据库、设置、私有资产

S6 本轮第一次面板检查启动失败后保留原始备份。核对系统桌面、原运行时及宿主身份后，
通过正常启动自己的应用完成受控恢复；private/public 哈希一致、宿主未变、原应用恢复
均单独留证。后续验收在恢复完成后继续，旧失败保留。

自动采集、原图 PNG/解码/查看器、缓存重开及合成夹具不等于纸面光学质量验收。
用户本轮无法再手扫，因此最新扫描预览／完成改动的真实纸面首开耗时不冒充已测。
此前 S6 手扫样本完整原图首次加载为 1567ms、缓存重开为 0/1ms、准备后完成为 194ms；
它只代表当时样本，不能承诺所有设备或所有原图首次打开低于一秒。
