# 联网搜索与图片引用（dev）

加号中的“联网搜索”默认开启，模型自行决定是否检索。设置里的“新聊天联网搜索”
可选默认开启、默认关闭或使用最近一次手动选择。历史菜单新建按该设置，上拉新建
继承上一会话。生成中修改开关只影响下一次提问。

搜索、阅读和图片获取显示在同一条 AI 回复里；点按可展开来源，再进入原生阅读页。
长网页分段阅读，不执行网页脚本。保存的是公开来源片段；需要更多内容可重新获取。
网页加载失败可手动重试，不会重新提交聊天请求。

AI 可以把实际获取的图片插在回答正文中，点击放大，双指缩放、单指移动、双击恢复。
图片只保存在 PenChat 私有资产中，随聊天备份，不自动加入系统相册。纯文字模型也能
引用有来源说明的图片；只有明确读图且支持图片的模型才收到像素。

## 协议与组件边界

- Responses：function call/output，保留必要的有序输出和同身份思考状态。
- Chat Completions：assistant tool_calls + tool 消息；视觉资料使用明确标记的用户
  图片资料消息，仅在 API 上存在，不创建聊天气泡或新问题。
- Anthropic Messages：tool_use/input_json_delta + 对应 tool_result，保持内容块顺序。
- 三者共用原生工具注册与执行、取消、额度、来源及图片资产机制。
- 编辑、重试、分支、归档、删除、压缩和导入导出复用现有数据库工作线程与引用保护。

官方协议依据：[OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling)、
[Chat create](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、
[Anthropic tool calls](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)。

## 2026-11-10：搜索 HTTPS 证书修复（dev，仍为0.2.34）

Y02 定向排查确认：模型 API HTTP 200，而搜索的四个引擎全部在 TLS 校验阶段返回
curl 60 / unable to get local issuer certificate。私有 curl 的交叉构建没有默认 CA
位置，worker 也未显式指定证书；固件存在系统 CA 文件并不足以使此构建自动使用它。

现随包携带 curl 转换的 Mozilla 公共根证书包，2026-11-05 版，118 个根证书，
200,116 字节，保持官方原文及 MPL-2.0 许可。worker 按自身可执行文件定位随包 PEM，
搜索、来源阅读及图片下载共用该设置；不引入主机私有证书，不关闭证书或域名校验。
构建与包检查验证资源哈希；缺失/无效资源返回明确工具错误，不使用不安全回退。

一并修复来源阅读器的预算冲突：原2MiB缓存小于上游默认文本+链接限额，无法初始化。
保留2MiB缓存，明确分配1MiB正文和256KiB链接限额，沿用上游截断标志及有界处理。

定向结果：

- `tests/test_web_trust.py`：官方资源/许可哈希、118个有效CA、可重定位路径及缺失、空、
  非PEM、超大资源检查通过；RK3562和CV1826-S编译及开发AMR静态检查通过。
- Y02安装后的真实组件：同一公开测试查询由0条/TLS失败变为Bing HTTP 200、10条结果；
  IANA示例域说明页HTTP 200，提取773字节正文。其他引擎仍可能要求验证或返回解析错误，
  不将搜索引擎风控误称为TLS故障。
- 自签名测试站点仍返回curl 60 / self signed certificate；测试目录缺失CA时返回明确
  工具错误。测试不调用收费模型、不写入聊天，设备临时探针已清理。
- Y02安装器返回成功并自动启动应用。整个私有目录的字节一致性检查因启动写入运行
  诊断等数据未通过，不能据此宣称全目录完全不变；未执行清库/恢复覆盖，数据库
  `quick_check`结果为`ok`。未重启系统宿主。

不升版本、不推送、不发布；无完整回归、ASAN或其他设备实测结论。

## 固定应用规则与正文原样保留（dev）

聊天请求由 `chat_instructions.hpp` 组合固定应用规则及用户/预设提示词。固定规则只约束
实际工具执行使用结构化通道、普通回答避免混入调用元数据、不虚构执行成功及结果。
不加入绝对禁止输出调用语法的规则，也不专门添加允许讨论工具语法的例外说明。
用户提示词及任务、语言、风格原样保留，不改写预设或会话设置。三种协议共用组合入口，
每次工具续答只组合一次；命名和压缩使用各自独立提示词。

按用户进一步要求，移除此前的DSML正文识别、流式扣留、显示/复制替换及上下文过滤，
不因回复内容包含协议标记而改判失败、删除续传快照或隐藏旧消息。用户询问工具语法时，
返回的DSML、XML、JSON等文字正常显示、复制并保留在历史中。
正文仍是正文：只有API正式工具字段进入注册表和执行器，不把文本示例猜成可执行调用。

AI正文长按菜单继续保留“复制全文、选择文本”，一行一项，至少48px；原复制/重试/分支
图标和生成期间规则保持原行为。选择基于打开菜单时的正文快照，不包含思考或隐藏记录。

定向入口：`tests/native/WebToolsTest.cpp`、`python3 tests/test_web_tools.py`。覆盖三协议
SSE/JSON、应用规则/自定义提示词各注入一次、工具语法原文保留且不误执行，以及历史
原文不被过滤。菜单三类布局截图及交互检查沿用上一开发提交的结果，不重复跑全套测试。
