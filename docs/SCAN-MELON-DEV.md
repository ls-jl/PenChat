# dev：MELON／OV7251、丢帧复核与扫描原图查看

本次为开发分支改动，不递增版本，不发布安装包。模型、32/24/8窗口、
逐帧亮度估计、动态内存保护和几何检查不变。

## MELON 采集配置

只接受 RK3562 MELON 与 OV7251 身份组合。依据用户提供的反馈与公开
`/usr/configs` 配置表，优先 ISP 自路 `/dev/video12`，候选主路
`/dev/video11`。节点必须具有对应 rkisp card/driver 身份，设置后必须实际
返回 640×480、单平面 NV12；逐帧校验 stride、有效缓冲长度及错误标志。
不接受当前低分辨率预览作为原图。

从本机 `hal_key_config.json`、`hal_led_config.json` 的 `RK3562_Melon_V0`
读取配置。扫描键通过 `led_control` 名称和 134 能力位发现，不固定 event
编号；Home 的 `adc-keys`／102 与扫描键分开，87 不当作 Home。
配置缺失、冲突或设备歧义时失败，不猜测。

仅操作配置中的 IR GPIO（当前表为43），不联动白灯44。已有 sysfs GPIO
须为可读状态的输出；未导出的 GPIO 仅通过原生 sysfs export 申请，失败
不 unbind、不抢占。新导出成功后写入本次租约的私有所有权标记，恢复时
只 unexport 有成功标记的 GPIO，避免 EBUSY 失败后误释放其他驱动资源。
父进程保留租约，子进程异常退出也能恢复格式、灯及系统 guardian。

标准 STREAMON 后最多2秒等待16个连续有效帧；只有完全没有收到帧才尝试
一次 OV7251 quick-stream，再等最多2秒。有帧但不稳定、格式错误或采集
错误直接失败。OV7251 不调用 SC2356 quick-only 或重复开流序列。
就绪后保持传感器连续采集，以笔头时间边界取帧；松笔不关闭传感器流。

中性校准由锁定的自有代码构造，身份为
`melon-ov7251-native-neutral-v1`，gain=1，继续逐帧亮度估计。旋转暂按
用户假设沿用 ORANGE／Y02 的逆时针90度；不是实测光学校准。
Y02 专属 NPU DMA 同步适配不扩大到 MELON。

## 统一缺帧规则

- 序号距离2～9：连续缺失1～8帧，可继续接受真实帧。
- 距离10及以上：连续缺失至少9帧，停止本笔新帧并处理已有内容。
- 多个小缺口只累计诊断与提示，不累计判停；序号回退／重置、非正时间
  差、采集失败、无帧超时及资源／几何保护继续生效。
- 不合成或插值缺失像素。界面不再将可继续采集描述成已恢复图像。
- 一旦漏采，扫描与确认页显示可换行的完整警告，并为警告让出图片区。
  部分结果保留使用／取消入口，正常结果同样必须经用户确认。

## 原图复核生命周期

完成且有可用图像时，点击预览打开现有全屏查看器。采集、处理、保存和
空结果不开放。原图准备使用独立 `prepare_review`／`review_ready` 操作，
携带会话、扫描ID、请求号和代次；不使用 `confirm`，不触发数据库写入或
自动发送。

后台线程从结果画布逐行生成私有 PNG，完成前不读低清共享预览来放大。
同笔结果重复打开复用已准备的原图。沿用查看器的有界解码、双指缩放、
单指平移、双击及16倍上限；准备失败可关闭后重试。

扫描来源的查看层不走普通聊天图片的 disarm 路径，不销毁待确认结果，
也不接受新一笔扫描。关闭返回确认页。后台、离开、断连和退出先取消／
等待原图准备线程，再释放画布及临时文件；健康模型仍常驻。
