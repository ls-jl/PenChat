# S6 原图采集重开修复记录

本次为 `dev` 开发修复，不升版本、不改拼接算法，不把硬件就绪或原帧测试等同于纸面画质验收。

## 可复现位置

设备为 S6 / CV1826 / PAG7920。使用独立 `s6-capture-probe`，始终采集完整
320×240 原始灰度，未接入 UI、OCR 结果或拼接模型的几何输出：

1. 同一个进程首次取得租约，连续获得 100 帧。
2. 释放 VI/ISP/VPSS 并恢复系统 CaptureFrame。
3. 同一进程再次取得租约。启动阶段的 API 全部返回 0，但 VPSS 连续两秒没有帧，
   报 `CVI sensor startup produced no continuous frames`。
4. 对照组保持独占租约，不让系统 CaptureFrame 在中间重建资源，直接关开采集三次，
   每次均持续获得 100 帧。

这独立复现了旧记录中的“重开后无连续帧”，与纸面运动、选帧、OCR 文本或合成器无关。
旧记录中的子进程退出没有可靠堆栈，本次不据此声称已定位所有退出原因。

## 原因与资源边界

旧实现将 `CVI_SYS_Init`、`CVI_VB_SetConfig` 和 `CVI_VB_Init` 放在同一个进程内
静态初始化中。VI/ISP/VPSS 在每次租约结束时关闭，但 VB 仍保持旧进程的初始化
标记、池索引和共享区映射。系统 CaptureFrame 重建它自己的 VB 共享状态后，
旧进程再次使用这些本地缓存，启动配置成功不代表帧池仍可正确工作。

通过已锁定版本的公开 API 及本地只读反汇编核对，`CVI_VB_Exit` 会释放池、解除
共享区映射并重置本地初始化状态。它与销毁 NN 模型、`CVI_SYS_Exit` 是不同的生命周期。

| 资源 | 生命周期 |
|---|---|
| SDK 依赖组、SYS 上下文 | 扫描进程常驻，不在每次扫描或 OCR 交接时重建 |
| 4KiB ION 锚点 | 进程常驻，避免已确认的最后一次 IonFree 后的供应商 hashmap 缺陷 |
| CVI NN 模型和输入／输出张量 | 保持原来的健康模型常驻策略 |
| VB 配置、池索引和共享映射 | 每次独占采集租约重新建立；VI/ISP/VPSS 和采集描述符关闭后，先 Exit，再交回系统 |
| 灯、笔头 evdev、guardian | 沿用现有租约获取、释放与身份校验恢复 |

本次不新增自动重载、失败重试、缩小原图、临时丢帧或重建健康模型。

## 修复与异常回滚

- 将 VB 配置与初始化移出一次性 SYS 初始化，每个 `CviCapture` 单独拥有。
- 创建进程 ION 锚点后再初始化 VB，VB 初始化未完全成功也走统一清理。
- 析构收尾不抛异常；`CVI_VB_Exit` 缺失或失败时记录明确阶段和返回码，并标记
  本进程 VB 状态不可复用。下一次 `verifyCviCaptureRuntime` 在暂停系统 guardian 前
  就拒绝采集，显示“采集池清理失败，需要关闭并重新打开 PenChat”，不能误当作可安全重开。
- 不调用广域 `CVI_SYS_Exit`，不卸载模型或改写供应商全局变量。

清理失败保护目前通过代码核对，未在真机强制制造 SDK Exit 返回错误。
