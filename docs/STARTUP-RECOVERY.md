# 启动与官方键盘故障恢复（0.2.16）

数据库构造的异常路径与正常析构共用清理函数：停止并唤醒工作线程、等待退出、关闭资产扫描目录、释放缓存语句和 SQLite 连接，再向调用者抛出原异常。覆盖打开、建表、迁移、线程创建及线程启动后的初始化 SQL。失败不会自动删除或重建用户数据库；主程序通过现有 `fatal` 消息报告错误，并以退出码 1 结束，启动器保留错误和重试入口。

官方键盘请求检查 IPC 发送结果。失败时清除等待标记及请求 ID，按前台状态恢复原生画面，恢复内置编辑器的面板策略、拼音查询和 OCR，显示可继续编辑/重试提示。正文、光标、选区、滚动位置及暂存拼音不提交、不丢弃；旧键盘结果不会误完成输入。诊断仅增加画面可见性与是否有提示两个状态，不增加输入内容。

## 验证

- 原生存储测试用触发器分别拒绝两条启动 SQL，各连续失败 20 次，检查异常可捕获、线程和文件句柄数量不变，并验证解除故障后重启恢复。原有迁移、分页、保存及资产回收测试保持通过。
- 实际进程验证启动错误通过 `fatal` 上报、退出码为 1、未触发 `std::terminate`，以及移除故障后可重新启动。
- 缩小真实 Unix socket 发送缓冲，令带长文本的 `keyboard.open` 因包长超限而发送失败；检查恢复后的正文、拼音、光标、选区、滚动、画面、提示及 OCR，拒绝旧结果并继续输入。普通官方键盘确认/取消仍由原键盘回归覆盖。
- ASAN/UBSAN 针对存储故障循环及官方键盘失败恢复运行。独立的“数据库失败、尚未创建 RichText 即退出”全进程 LeakSanitizer 检查发现上游 MicroTeX 预初始化宏注册表的 7,056 字节进程退出期泄漏；该入口仅在普通构建验证退出流程，没有新增抑制规则，也未将这一全进程泄漏检查计为通过。
- AArch64、生产 AMR、许可证及身份检查通过；环境检查仍有已有的可选 cnpm 提示。设备截图及日志放在忽略目录，不携带用户数据。
