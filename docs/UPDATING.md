# 在线更新

PenChat 0.2.21 起提供离线保留旧版的在线更新。0.2.20 及更早版本需要手动安装一次。更新源固定为 `https://cdn.ls-jl.cn/penchat-rk/`，只接受规范的三段整数目录，使用整数比较。启动检查一次，设置中可手动检查；自动提示只在聊天根页面空闲时显示。稍后或主动取消会持久记住目标版本，手动检查可再次打开。

0.2.23 起，客户端只使用 `/penchat-rk/` 路径，不回退到原路径。服务器目录由部署方另行配置；本次客户端修改不发布或调整服务器文件。

## 发布约定

每个版本目录必须恰有一个 `.amr`，建议总是提供其同名 `.amr.sha256`。摘要支持纯 SHA-256 或 `sha256sum` 输出；错误摘要不允许绕过。只有校验文件完全缺失时，首次下载按钮明确询问是否继续。`release-note.md` 必须准确命名；所有已落后且不高于目标的版本说明按升序提供版本及分页浏览。

上传先放非版本临时目录，核对两个节点上的文件长度、哈希与唯一安装包，再原子改名发布版本目录。已发布版本不可覆盖；修复必须使用更高补丁版本。一个节点完整发布即可更新；两节点文件名、长度、SHA-256 相同时才允许合流。异常版本回退到下一可用新版。

## 原生实现与边界

`update_package.cpp` 负责受限目录链接、版本、哈希、ZIP 路径/CRC/大小/AppID/版本及空间检查。上限为安装包 256MiB、展开 512MiB、20,000 条 ZIP 记录。禁止符号链接、重复路径、绝对路径及路径穿越。更新说明每份最多256KiB，缓存总量8MiB；过大的说明明确提示，缓存淘汰后按需重读，不静默跳过版本。

`update_transport.cpp` 使用独立 CURLM 与工作线程，不占聊天网络槽。原生解析 DNS，保留域名 URL、Host、SNI、HTTPS 校验和环境代理，通过 CONNECT_TO 选择地址；DNS 不可用但代理可解析域名时退为单源。每个候选节点进行三轮 HEAD，取 TTFB 中位数。仅保留两个确认同包的节点。

1MiB 分段使用有界写入和 pwrite；从1路开始，每秒最多加1路，总共不超过8路。首字节开始3秒后，主节点3秒窗口速度低于250,000字节/秒才启用同包第二节点，或者在已确认的主节点失败时接续。Range被忽略时退为单路完整下载；不把200正文当作分段。临时失败每段最多两次重试。取消/退出删除未完成文件；首版无跨进程下载续传。

下载与所有校验成功后保存恢复快照和安装票据，排空数据库队列，释放扫描、相机、OCR、触摸与显示，退出旧原生进程。Falcon 启动桥接提交安装，然后读取包管理器实际版本；回调状态本身不构成成功证据。票据保留结果未知与失败状态，不自动重复提交；手动重试须重新校验。新进程核对实际版本，恢复会话、空聊天偏好、草稿和阅读位置，待发图片沿用数据库关联。

113实测 JS `pm.installPackage` 对第三方应用返回100（Permission denied）。经用户确认，使用 Falcon 导出的原生包管理方法，以动态符号发现；不修改权限、不使用对象字段偏移、不伪造其他AppID、不执行shell。原生桥接只接受自身数据目录的 package.amr，重新验证包身份/版本/SHA/CRC后提交。固件不提供对应导出时明确失败，保留已校验包与旧数据。

发布异常复用反馈队列，只含AppID、应用名称、当前/目标版本、异常类别及必要计数。按AppID和版本持久去重，每版最多一次自动请求，无自动重试；失败可在反馈记录手动处理。自动报告最多占9个队列槽，满时保留待发标记，不删除用户反馈。更新不依赖上报成功。没有私有上报配置的公开构建仍可使用更新。

## 测试入口

- `python3 tests/test_update.py`：真实原生探针、可控双节点 HTTP/TLS、版本回退、SHA、ZIP、恢复票据、限速合流和取消。
- `python3 tests/test_update_ui.py`：两种尺寸的原生页面、长说明、缺失校验提示、取消与编辑器不中断。
- `node --test tests/js/update.test.cjs`：安装交接去重、真实版本核对、超时与旧回调、原生安装失败不隐式切换。
- `tests/test_feedback.py`：发布异常的最小报告、自动一次、重启去重及手动重试。
- `penchat-update-probe` 是测试目标，不随AMR发布。配置覆盖、测试CA与消息注入仅主机有效；生产更新地址不可配置。
