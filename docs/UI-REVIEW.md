## 截图与复现

交付工作区 `.work/ui-audit/index.html` 提供 53 个状态的截图对照，可筛选页面并点击原图。
包含所有 12 个原生页面，以及历史抽屉、菜单、弹窗、旋转状态、启动器和系统输入法。
部分补充状态没有旧截图，报告明确标注；不将其冒充前后对照。
截图以测试数据生成，启动错误页来自主动结束测试原生进程后验证重试；不是用户使用中的崩溃。

- `npm test`：实际 LVGL 进程回归及常用页面截图。
- `python3 tests/capture_ui.py --output .work/ui-audit/after/extra`：补拍表单、选项、OCR、非空相册及空状态。
- `python3 tests/device/presets.py`、`python3 tests/device/photo_orientation.py`：ORANGE 真实触摸、预设与四向拍照/裁剪。

- `python3 scripts/ui-gallery.py`：从已有截图生成本地对照页和 manifest；运行前需完成上述截图流程。

截图、测试数据库、构建产物不进入 Git；复现脚本和检查结论保留在源码中。

## 0.1.33 设置页

设置页沿用48px固定页头与一个纵向滚动正文。功能入口和选择器右侧使用原生箭头，
四个布尔设置使用蓝/灰原生开关，整行是唯一点击目标。名称20px、说明16px，均单行省略。
命名模型在自动命名关闭时仍可配置，失效引用保留并提示；压缩和导出目录说明就近显示。
命名模型选择器支持长按查看完整名称，详情通过UI事件队列打开，不触发模型选择。
进入子页面前记录滚动位置，返回及原地切换设置时恢复；从聊天抽屉重新进入则回到顶部。

`python3 tests/test_settings_ui.py`覆盖11项可达性、长值、开关点击/持久化、滑动误触和返回位置，
截图输出`.work/settings-ui/`。`npm run test:device:settings`在ORANGE隔离私有数据和公共导出目录
进行真实触摸验证，结束逐文件恢复用户目录，不重启系统宿主。

首次启用图片自动发送同时覆盖缺省配置：先读取布尔值，再写入JSON，避免设备GCC 6/C++14
对赋值两侧的求值顺序导致新键先插入null、读取布尔值失败。主机编译器的求值顺序无法替代此项真机验证。

本版完整主机回归通过；最终设置专项、历史/推理选择回归及ASAN/UBSan通过。
AArch64及生产AMR身份、资源、许可证清单与strip检查通过。ORANGE已验证全部11项入口、
四个开关的整行/开关点按、缺省配置首次切换、子页面位置恢复及完整模型名查看；
验收后逐文件恢复私有和公共目录，宿主PID保持不变。CLI环境检查仍仅提示可选cnpm未安装。

## 所有业务页使用滚动标题（0.1.36）

Provider列表与编辑、模型与参数映射、预设列表与编辑、归档、相册、导入导出的标题与页头操作
统一放入同一个全高滚动区。上滑时一起移出，业务控件可使用屏幕顶部，不保留空的标题栏。
短列表无需人为增加空白来强迫滚动；长表单原地修改后保留位置，不因为重建控件跳回标题。
设置的子页面返回位置规则继续沿用。相机、裁剪保留完整工作区；扫描移除重复页面标题，预览多使用48px高度，
指引、使用图片和取消按钮仍直接可见；扫描采集和拼接实现不变。

实现约定：`body_`始终代表实际滚动视口，`pageHeader()`创建流内标题和`pageContent_`，业务控件加入`pageContent_`，
页头操作使用`pageAction()`以避免标题重叠或出现固定浮层。切换表单或分页时重置位置，同一表单重建时保留；
这些位置只存在于进程，不修改数据库或桥接协议。`page`诊断仅包含视口、标题、操作按钮边界和滚动状态。

`tests/test_page_flow.py`在两个设备尺寸生成48张逐页首屏/滚动截图，覆盖列表、表单、归档、相册、传输和工作区；
扫描结果截图由原有扫描集成测试提供。`tests/device/page_flow.py`复用完整私有/公共目录隔离，在ORANGE进行逐页真实触摸检查。
截图放在忽略的`.work/page-flow/`与`.work/device-acceptance/flow-*.png`，不提交设备数据。
