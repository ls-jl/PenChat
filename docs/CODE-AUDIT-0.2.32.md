# 0.2.32 代码可达性与资源清理

基线：0.2.31（a0b41c0）。本轮按入口、回调、跨进程导出、构建目标和测试引用检查自有源码；不以单次文本搜索或删除行数判断死代码。未改数据库、AppID、API 协议、扫描数值算法或键盘交互。

## 检查范围与保留规则

检查原生 UI 的页面/动作、异步结果和生命周期入口，启动器与桥接导出，显示/相机/图片工具，网络/存储/拼音/扫描接口及其构建与测试引用。对低引用计数项再次检查调用路径。

- MicroTeX 图形虚方法仍由第三方动态调用，保留。
- 启动桥接导出及扫描器的 `system` 阻断、`ioctl` 适配具有动态绑定用途，保留。
- 旧库迁移、协议兼容、硬件恢复和有实际调用的导航/布局接口保留。
- NV12 仍是采集格式；删除的是已不使用的独立 NV12 显示通道，不是采集或颜色转换。
- 原始 Camera 来源记录、第三方许可证、过去版本的验收证据保留。历史说明明确标识为历史，修正一处容易误读为当前约束的磁盘上限说明。

这不是形式化的全程序可达性证明。没有充分调用证据的分支保持原样；没有调整第三方内部算法。

## 可测的优化与修复

1. 相机不再每帧复制一份无人读取的 NV12 快照。960×720 时少保留 1,036,800 字节，并去掉对应逐帧复制；正在保存照片的局部原始像素仍有效。
2. LVGL 已为 BGRA，DRM 也使用 BGRA。删除 BGRA→RGBA→采样→BGRA 的两次整帧转换及常驻 RGBA 副本；诊断截图按需转换。没有修改采样和旋转数值行为。
3. Overlay 记录是否成功提交，关闭/隐藏前查询实际 framebuffer 所有权。尚未呈现或已被新 owner 替代的对象不会清空别人的画面；析构释放自己的 libdrm 引用。
4. 显式指定 V4L2 节点后不再偷偷尝试其他节点；高清拍照路径失败会如实报错。未指定设备时仍按现有发现规则选预览节点。
5. 修正 Camera 读取工具最后一块可能超过 maxBytes 的问题，并重试 EINTR。边界测试包含空上限、二进制 NUL、4095/4096/4097 字节和文件结束。
6. 为 CaptureProfile 增加显式构造，消除聚合初始化产生的自有代码告警，字段默认值不变；更新自有适配文件锁。

### 像素处理微基准

同一可执行程序内顺序测量旧路径与新路径，各12次；下表是设备上的整幅采样/通道处理平均耗时，不是 UI 整页帧时间，亦不包括网络/渲染/DRM 提交。测试尺寸是固定回归样例，运行时屏幕几何仍读取 Falcon。

| 设备及样例 | 旧路径 | 新路径 | 省掉常驻转换副本 |
|---|---:|---:|---:|
| ORANGE，960×266 | 7.100ms | 4.774ms | 1,021,440字节 |
| Y02，936×280 | 25.250ms | 16.774ms | 1,048,320字节 |
| Y07，568×1210 | 65.273ms | 43.727ms | 2,749,120字节 |

频率及系统负载会影响结果，不作为固定帧率承诺。真实 DRM 读回在三台设备均与旧路径逐字节一致。

生产 AMR 从21,066,656字节变为21,049,801字节；主程序从9,761,696变为9,735,792字节。
扫描程序从420,944变为425,760字节（Profile 构造方式及编译布局变化），未改动扫描算法。
包体减少不是此次清理的主要收益；每帧复制、常驻像素缓冲与显示所有权更重要。
