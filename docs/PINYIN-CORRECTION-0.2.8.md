# PenChat 0.2.8 拼音纠错验收

## 用户行为

设置 → 键盘与输入 → **拼音纠错**，默认开启。26键输入漏字、多字、邻键或
颠倒字母时，补充蓝点候选；长按显示正确拼音，长按松手不选词。
例如 `nihoa`、`nihxao`、`nihqo` → 你好，`zhngwen`、`zhognwen` → 中文，
`zhogn` → 中。原始拼音始终保留，Enter仍上屏原字母；空格/完成沿用选词逻辑。

完整精确拼写有正常解释时不尝试纠错；完整简拼候选也排在纠错之前。
因此 `niao` 仍是“鸟”，不会猜成“你好”。部分本身合法的错拼不会被纠正。
本轮不加入模糊音，不改变九宫格、英文、OCR或官方编辑器，不扩大词典。
词典与音节表仍合计 **1,253,849字节**，其来源和资源校验值保持不变。

## 实现边界

- 复用音节Trie，单个4～32字母组合至多一次插入、删除、相邻替换或相邻颠倒。
  替换邻接依据QWERTY键位，不依赖设备像素；颠倒可跨音节但不能跨显式分隔符。
- 额外搜索上限16,384次状态扩展、256项中间结果，去重补充最多8项。
  单字纠错须覆盖全部原码；不把精确词后的单个尾字母直接吞掉。
- 正确拼音与消费的原码位置分别保存；部分选词后保留剩余原码。
  查询/选择校验编辑会话、修订号、候选版本、布局和纠错开关快照。
- 仅完成编辑后学习正确拼音和所选词；取消、原码回车、密钥、OCR和粘贴不学习。
  词典只读、私有学习文件格式及其10,000条/2MiB上限不变。
- 引擎改动通过源码补丁及SHA256锁定。应用设置新增 `pinyin_correction`；
  数据库结构、AMR桥接及依赖不变，资源损坏时仍可保留输入并手动使用官方入口。

## 固定样例与性能

`evaluation-correction.json` 为40条人工单错样例，包含错拼本身有合法解释的情况。
这不是通用语料准确率或系统输入法对标；不因未命中就放宽保护规则。

| 样例 | 关闭纠错 | 开启纠错 |
|---|---:|---:|
| 26键正常输入，首选 / 前五 | 70/73 / 73/73 | 70/73 / 73/73 |
| 九宫格正常输入，首选 / 前五 | 62/70 / 67/70 | 62/70 / 67/70 |
| 40条错拼，首选 / 前五 | 9/40 / 11/40 | 27/40 / 28/40 |

143条正常输入的前48项候选逐项一致；关闭纠错保留原算法结果。
主机交替9轮的26键正常查询P95中位数为0.211→0.216ms（约+2.2%）。

113设备（MEA2300009007113）同批交替9轮，未锁定DVFS：

| 指标 | 结果 |
|---|---:|
| 正常26键查询P95，关闭→开启 | 2.723→2.695ms |
| 错拼查询P95中位数 | 5.199ms，低于20ms目标 |
| 正常查询进程峰值RSS中位数，关闭→开启 | 13,592→13,592KiB |
| 固定错拼集观察到的最大状态扩展 | 4,967次，上限16,384次 |

计时排除词典加载、35ms查询合并、UI调度和绘制；轻微速度差异属于未固定频率下的
批间波动，不宣称纠错加速正常输入。运行结果写入 `.work/pinyin-correction/benchmark.json`；
本次设备测量写入 `.work/pinyin028/device-benchmark.json`。
