# 账户余额查询（开发分支）

历史抽屉底部的钱包图标位于新建聊天与设置之间。打开“账户余额”后，立即刷新所有已启用查询的 Provider；也可全部或逐项手动刷新。每次进入都查询，没有60秒缓存拦截。

在模型管理的 Provider 连接设置中选择“余额查询厂商”，保存后生效。默认“不查询”，不会根据模型名称猜测厂商。此选项不修改聊天协议、模型、密钥或厂商参数适配。

| 厂商 | 官方主机及GET路径 | 展示 |
|---|---|---|
| DeepSeek | `api.deepseek.com/user/balance` | 各币种总余额、赠送、充值 |
| Kimi | `api.moonshot.cn/v1/users/me/balance` | 可用、现金、代金券，CNY |
| 硅基流动 | `api.siliconflow.cn/v1/user/info` | 总余额、充值、非充值余额，CNY |
| 302.AI | `api.302.ai/dashboard/balance` | 账户余额，未确认币种时标为“平台单位” |

仅允许匹配上述HTTPS官方主机和443端口。Base URL可以包含正常API路径，但不接受用户信息伪装、非官方域名、HTTP或自定义端口。查询使用本Provider的Bearer Key；不将中转Key发送到官方，也不读取普通聊天返回内容猜余额。302.AI的Key需要在服务商端开启余额查询权限。

金额在解析时保留十进制原文，不通过浮点加减推算；微小值、零和负值均保留。缺失或格式错误不能当零。硅基流动返回停用/空状态时提示控制台核对，不把可疑占位数据当作有效余额。服务商接口是否仍向具体账户提供有效余额，需要实际账户验证；本文不声称已完成四家真实联调。

两个后台工作线程共用现有原生HTTP服务，最多并行两项，每项总超时15秒，不自动重试；响应限制64KiB和12层JSON。失败仅返回本地固定错误文案，不输出服务端原文或密钥。Provider的余额厂商存入既有元数据，结果只存进程内；诊断仅记录查询状态，不包含金额或用户资料。

离页、后台及退出取消任务；配置身份及代次隔离旧结果。重新查询失败时保留最后成功的金额和时间，并明确标注“刷新失败，以下为上次结果”。回到聊天保留会话、草稿、待发送图片及阅读位置。

定向验证入口：`penchat-balance-tests` 与 `tests/test_balance_ui.py`。UI用例使用仅主机编译可用的注入文件，不读取真实服务商凭据或发起公网余额请求；设备二进制不包含此注入入口。三类布局截图为虚构数据，仅写入忽略的`.work`目录。

接口来源：[DeepSeek](https://api-docs.deepseek.com/api/get-user-balance/)、[Kimi](https://platform.kimi.com/docs/api/balance)、[硅基流动](https://siliconflow.readme.io/reference/user-info)、[302.AI](https://doc.302.ai/262796252e0)。
