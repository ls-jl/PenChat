# 键盘设计配置与按键模板

键盘使用编译期 C++ 配置，修改后重新编译原生 UI 生效。三类屏幕布局与短横屏展开视图
共用配置、控件样式和按键模板；默认参数保留本次重构前的配色、字号、键序和布局。
本方案没有运行时配置文件、热加载入口或用户换肤设置。

## 调整入口

| 想修改什么 | 修改位置 |
| --- | --- |
| 公共键帽颜色、圆角、透明度 | `native/lvgl-app/src/keyboard_design.hpp` 的 `KeyboardDesign::base` |
| 功能键、候选、菜单等同类控件 | `roles[KeyboardRole::…]` |
| 单独的删除键、无边框地球、收起图标 | `variants[KeyboardVariant::…]` |
| 字母、键帽功能文字、操作按钮、候选、组合、菜单、编辑文字 | `typography.sizes[KeyboardFont::…]` |
| 仅某种布局的字号 | `profiles[KeyboardView::…].fonts`；0 表示继承公共字号 |
| 键间距、行间距、外边距、命中扩展 | `keys` |
| 组合条宽度、候选行和展开按钮 | `composition`、`candidates` |
| 三类布局的空间分配 | `wide`、`compact`、`portrait`、`controls` |
| 弹层圆角、语言菜单尺寸、放大镜尺寸与位置 | `popups` |
| 图标大小 | `icons` 中的比例；路径仍由共享 `icons.cpp` 绘制 |
| 按键顺序、显示内容、宽度规则 | `native/lvgl-app/src/keyboard_keys.hpp` 的行模板 |

颜色引用应用共享的 `theme.hpp`。`background` 是键盘底板，`popupBackground` 是弹层底板；
菜单项由 Menu 角色决定。半透明控件的最终颜色还取决于底板，调整时需要一起查看。

## 样式与字号

样式解析顺序为公共默认、控件角色、命名变体、交互状态。`KeyboardStylePatch` 的 -1
表示继承，0 是有效值（例如完全透明）。选中状态先选择底色，按下覆盖按下反馈；禁用
时不显示按下反馈，并应用禁用透明度。Shift 的大小写／锁定图标仍由输入状态决定。

字符键和功能键的默认样式相同，但有独立角色。`KeyFunction` 是空格、模式切换等
键帽文字；`Function` 是完成、取消等操作文字。竖屏菜单和短横屏展开操作字号保留
现有覆盖。输入字段原有19px与20px字体分别归入 InlineField 和 Editor。

例如在 `KeyboardDesign` 的默认值或构造函数中调整：

```cpp
base.radius = 12; // 字符键、功能键共用；已有独立圆角的候选等角色不变
roles[size_t(KeyboardRole::Function)].pressedBackground = theme::accent;
variants[size_t(KeyboardVariant::DeleteKey)].foreground = theme::danger;
profiles[size_t(KeyboardView::Portrait)].fonts[size_t(KeyboardFont::Character)] = 26;
```

按钮文字始终单行省略。独立编辑区应用 Input 角色的背景和圆角；竖屏原字段编辑保留
页面外框与背景，共用字体、光标、选区配置。编辑测量、光标、选区、自动滚动和放大镜
读取实际编辑字体；候选用同一字体测量与绘制。

## 坐标与模板

真实屏幕尺寸、旋转和安全区来自 Falcon 和共享 AppLayout。`compact.splitCanvasWidth`
与 `splitCanvasHeight` 仅是原有短横屏展开视图的内部设计画布，不是设备分辨率回退。

未缩放布局中的尺寸为 Falcon 逻辑像素。短横屏展开视图沿用原有整体变换：文字、圆角
与局部尺寸在设计画布上定义；键间距、行间距、键区外边距先逆换算以保持逻辑屏幕间距，
操作目标也保持最小逻辑触摸尺寸。需要调整展开视图的字感时使用其字体覆盖，避免第二次
按物理屏幕缩放。位置和宽度保留原有直接计算及取整，避免累加浮点误差造成1px漂移。

`KeySpec` 的 id 是稳定身份，action 是既有输入动作，caption/icon 是显示内容，role/variant
决定外观。字符 caption 与 action 相同时，中文标点和 Shift 由界面解析；显式改写 caption
会保留自定义文字。空格 caption 为空时显示当前输入语言，其他功能键保留模板文字。`KeyRow` 按顺序排列键；宽度规则如下：

- Equal：当前布局计算出的字符键宽度。
- Fixed：给定的局部宽度。
- Relative：字符键宽度 × 系数 + 固定偏移 + 键间距 × 系数。
- Remaining：分配本行扣除其他键和间距后的剩余空间。

例如把底行回车改为 `KeyWidth::relative(2, 8)`，其余键保持原规则，空格会相应缩短。
重排模板记录不会改变 action。26键仍采用现有十列宽度基准，9键采用三列与左侧筛选栏；
新增不同列数或不同输入逻辑需要扩展布局或状态机，不通过任意表达式、脚本或匿名回调配置。

`EditorLayout::placeKeys()` 同时输出键帽与命中矩形。独立触点始终使用同一矩形和角色；
调整键宽会连同命中范围更新。配置导致非正键宽或一行超出可用空间时明确报错。
活动触点期间不重建键帽，候选和正文保持局部刷新。

布局构造接受只读配置引用，只保留后续需要的几何值，不保存配置引用。模板只在结构
重建时创建；逐键输入不会复制整个设计配置。编译期默认配置不包含设备能力或用户数据。

## 验证方法

主机配置专项为 `penchat-keyboard-design`，覆盖公共／角色／变体／状态优先级、字体
覆盖隔离、单键加宽、空间重新分配、命中同步、键序变化、临时配置寿命和真实字体测量。
`penchat-platform-layout` 与 `penchat-magnifier-layout` 保留布局边界检查。

`python3 tests/test_keyboard_design.py` 使用实际 LVGL 进程，覆盖960×266、936×280、
640×260、720×280、568×1210、600×1280及展开／互换。可传入
`--baseline <旧主机程序绝对路径>` 对照默认键位、命中范围、编辑区和候选区域；截图和
诊断默认保存到忽略目录 `.work/keyboard-design`。这些尺寸均为测试夹具。

再按受影响部分运行现有键盘、快速输入、双触点、候选、光标、字段切换、OCR与系统输入法
定向测试。测试使用私有目录和虚构输入，默认不操作设备。验证记录与截图不提交 Git。
