# 重试结果与继续聊天定稿

最新回复直接重试。设置“聊天与会话”中的“重试前提示归档”默认关闭，
开启后只有较早回复弹出三项小菜单：取消、归档当前聊天并重试、直接重试。
改变此开关不追溯撤销已选的归档意图，回复下会显示发送时归档的提示。

首次结果为1，重试依次编号。完成保存后，回复操作栏右侧提供左右切换。
生成时整条操作栏仍隐藏。新结果暂时隐藏后文；选回首次结果恢复后文和
其中的选择状态。草稿、待发送图片、模型选择和全局默认值不随切换改变。

下一条新消息成功入库时，才在一个事务中固定有效路径、可选归档、清理
候选和后文、重排待发图片，并写入下一条问题及助手占位。发送准备失败
不定稿。事务成功后网络失败不恢复旧候选，也不会自动重发。

内部schema从2兼容升级至3，SQLite备份在DDL事务之前持久发布。新增
reply_groups、reply_results、reply_asset_refs；原有业务表结构不变。原消息
保留当前选择的内容，结果表保存独立正文、思考、请求快照、时间、工具
记录和协议私有状态。原后文在定稿前不删除。重启将未结束结果标为中断，
不重放请求。准备阶段已取消且未启动请求的占位可以原子撤销。

分页、请求和压缩通过同一有效视图读取；多处结果以最早的非首次结果为
当前截止点。分支、备份和导出只读取所选路径，不因此清理源会话候选。
复制全文、文本选择和图片浏览始终针对当前选择。工具签名及加密内容
继续受原有请求身份规则约束，不跨兄弟结果续传。

资产引用持久保护候选和归档原图，删除仍走后台回收，不修改系统原件。
所有请求的用量仍计入累计；清理的结果只留下有界的统计计数，不留正文。

定向入口：penchat-reply-choices、penchat-reply-actions、penchat-context、
penchat-usage、penchat-transfer、tests/test_reply_choices.py。使用虚构配置和
本地服务；截图、私有安装备份与日志不入Git。升级后的数据库不能由旧程序直接读取，恢复旧程序前需要使用升级前备份；不要覆盖新产生的数据。

本轮定向验证：五项原生回复／迁移／压缩／用量／传输用例通过，包含
DDL冲突、SQLite容量耗尽、写入请求快照失败及事务回滚。实际进程界面
覆盖三类布局、三种协议、默认关闭和较早提示、最新绕过提示、多处结果、
恢复后文、重启及150%字号。HTTP失败重试回归通过，未自动重发。
AArch64与ARMv7开发包通过身份、资源、架构和剥离校验。
未执行全套发布回归、sanitizer或自动真机手势验收；真实服务未调用。
