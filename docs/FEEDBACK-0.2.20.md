# PenChat 0.2.20 反馈功能验收

## 实现

原生反馈服务、白名单环形诊断、只读设备信息、短时物理按键向导、持久化发送队列与重试，以及设置内表单/预览/记录。AppID 和数据库结构保持不变，扫描算法和常驻策略未修改。配置与隐私约定见 [FEEDBACK.md](FEEDBACK.md)。

- 原生网络增加连接目标覆盖及 Retry-After、curl 错误码；反馈连接与 Provider 分区隔离。
- DNS/指定节点轮换保留 TLS 校验和域名。只有 201 + 布尔值 ok:true 成功；不自动上传完整日志。
- 后台队列限制 10 份 / 10MiB，单报告 1MiB；成功清除正文，失败保留；同一编号/正文重试。
- 退出取消并 join 上传和按键线程；无工作时按最近调度/1秒唤醒，而非持续轮询写盘。保存异常暂停自动发送，避免磁盘错误时空转。
- 提供开始监听就绪状态，首次按压不会被初始化清理误当成旧事件；后台扫描步骤取消时保留已有事件，缺少松开明确标记。
- 显示预览编号校验，重复预览等待新报告；失败通知在异步刷新后保持可读。

## 主机

`npm run build:host`、完整 `npm test` 通过，包括 14 项 CTest、桥接、实际 LVGL 进程、数据库/导入导出、三种 API、图片/键盘/扫描回归。

反馈专项 `tests/test_feedback.py` 共 14 项，覆盖：

- 白名单隔离（主动注入正文/密钥/URL/序列号哨兵）、500条/256KiB 和上一运行。
- 成功、401/404/413、HTML、无效201/200回执、5xx/507、3次重试耗尽、429较长 Retry-After。
- 编号及正文一致、停止/手动重试/删除、进程重启、进行中取消、过大回执、损坏文件及临时文件清理。
- 10份队列上限、目录不可用、运行中写盘失败后的采集恢复与提交去重、过期按键结果、2000字限制、按下后中断恢复。
- 本地可信测试证书验证 TLS，域名→指定IP后 Host 与 SNI 仍为原域名；未关闭证书验证。
- 公开构建未配置服务、错误私有配置不回显凭据。

`tests/test_feedback_ui.py` 检查 960×266 / 936×280 表单、内置编辑器与官方手动入口、向导、预览、记录、设置返回位置，并使用本地401服务检查通知不被下一次重建清除。截图在忽略的 `.work/feedback-ui/`。

针对反馈服务及上述实际 UI 流程完成 ASAN/UBSan；沿用项目已有 MicroTeX 泄漏抑制，不新增抑制项。

## 构建与服务

AArch64 编译、生产 AMR 检查、45份许可证/资源完整性、10个生产 ELF strip 检查通过。`aiot-cli check` 仍仅提示可选 cnpm。

真实服务仅发送 **1份明确标记的合成报告**，未包含用户数据或设备信息，收到 HTTP 201 / ok:true。异常状态及节点轮换使用本地模拟，没有向真实节点额外发探测或故障请求。

私有构建配置、真实令牌、报告、设备采集和截图均未加入 Git。令牌会存在于实际原生安装包，不能视为不可提取的秘密。

## 设备

Y02/113：实际 Falcon 配置 936×280、显示与触摸方向270度。隔离私有目录和公共导入导出目录后测试；四角映射、反馈入口、扫描按下、系统 Home 离开/返回、采集记录恢复、预览及监听关闭通过，用户文件按哈希核对还原，宿主 PID 未改变。测试由真实触屏事件及辅助程序注入的按键对驱动，不等同于人工手持扫纸/按键体验。
