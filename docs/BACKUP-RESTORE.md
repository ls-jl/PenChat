# 增量还原备份

入口是 **设置 → 还原备份**，与“检查更新”同级。软件更新页面和 Falcon 版本回退页面不重复放入口。列表读取本应用 `data/.rescue/backups/<UUID>/` 中的完整回退备份；没有备份时说明如何通过版本回退的“备份并安装”创建。普通聊天导出文件继续走“导入与导出”。

## 用户操作与增量规则

1. 选择备份，后台校验完整文件清单及数据库，不直接覆盖当前 `.db`。
2. 当前没有的项目加入还原清单；已有聊天或配置逐个显示“替换”和“跳过”。勾选“全部冲突”后，再点任一个操作，会把该选择应用于本次所有冲突，包括先前已选择的冲突。缺少的新项目仍然添加。
3. 最后显示新增、替换、跳过数量，点击“开始还原”才提交。此前取消不会改动当前用户数据。全部跳过且没有新增项时不重载界面。
4. 成功后重新打开本应用的原生界面，返回还原结果。系统 MiniApp 宿主不重启。源备份保留。

聊天按稳定会话 ID，服务商／预设按稳定 ID，设置按键名判断；同名但不同 ID 通常是新项目。模型还需遵守数据库的 `(provider_id, name)` 唯一约束：匹配已有自然键时沿用目标模型 ID；ID 与自然键指向不同模型时拒绝，不能猜测覆盖对象。

“替换聊天”是整个聊天及其草稿的替换，包括物理消息、隐藏的回复分支、压缩记录、图片引用和附件；不做逐消息合并。其他聊天及其图片保留。服务商、模型和单个预设按完整记录替换；全局默认服务商／模型分别确认。共享新聊天草稿、输入法学习记忆和公共传输文件也分别按项目处理。不会恢复运行日志、安装票据、任务缓存或旧的活动会话指针。

只恢复已保存的本地数据，不重新发送历史模型请求；未完成输出标记为中断。恢复的聊天关闭历史自动命名任务，保留用户原文、签名及身份限定的不透明模型状态。图片复制到新的私有路径，不能覆盖跳过聊天仍在使用的图片；系统相册原图不动。恢复设置后主题、缩放和键盘记忆随新原生界面载入。

## 严格校验与支持边界

- 仅本应用私有备份目录中的 UUID 条目；检查 manifest format、AppID（提供时）、每个路径、大小及 SHA-256。拒绝路径穿越、链接、特殊文件、重复路径及清单外文件。旧 format 1 缺少来源字段时仍可接受，但必须通过同样的结构、数据和文件验证。
- 清单最多 16MiB／100000 条，目录最多 64 层，单文件最多 512MiB，还原项目最多 10000 项；JSON 有深度／节点预算。每次复制检查剩余空间并保留 16MiB 余量。超限明确拒绝。
- 当前只接受 **schema 3 且表字段与当前版本一致**的备份。先在私有暂存目录复制数据库及 WAL／回滚日志，交由 SQLite 恢复，再生成独立快照。SHM 不跨 ABI 复用；不修改原备份。流程依据 [SQLite 文件格式说明](https://www.sqlite.org/fileformat2.html)。
- 检查 SQLite 完整性、外键、唯一身份、消息／附件／回复分支归属及 JSON 字段；拒绝未知表、视图、触发器、虚拟表、畸形快照和非法配置值。所有需要恢复的本地图片必须有清单文件。
- 确认期间若备份或当前数据发生变化，提交失败并要求重新核对。UI 回调、后台事件和计划都绑定代次／身份。生成、编辑、图片处理或更新未结束时不开始还原。

校验通过不代表任何历史数据格式都能导入。较新／较旧 schema 或损坏备份会拒绝，而非清库或隐式迁移。

## 事务及中断恢复

校验和计划在后台运行，实际业务变更只通过现有单 DB worker。应用先正常结束编辑、网络及资源线程，再提交，防止旧 UI／IME 的退出写入覆盖已还原内容。

公共文件与 IME 使用旧／新副本及持久化事务清单 `.rescue/restore-journal.json`；数据事务同时写入 `_restore_operation` 标识。文件和清单先 fsync，再提交 SQLite。数据库失败时撤回文件变化。进程中断后，下次启动在数据库初始化／图片清理之前核对提交标识：未提交则回滚文件，已提交则校验并完成清理，不重复执行还原。遇到被外部修改的文件或校验不符时保留事务现场并阻止继续覆盖。

结果保存在 `.rescue/restore-receipt.json`；临时文件在 `.rescue/restore-stage/`，完成或取消后清理，未核对的事务保留以便恢复。备份含聊天和服务商密钥，留在本机，不自动上传；不要将原始备份公开分享。

## 开发检查

`npm run test:backup-restore` 运行隔离 SQLite／文件和真实 LVGL 测试。可单独构建 `penchat-backup-restore-sanitize`，使用 `PENCHAT_BACKUP_RESTORE_PROBE` 指向该目标执行后端检查；其 ASan/UBSan 范围为还原服务及 Database 业务源，不是全量渲染 sanitizer。

本批验收原始记录、截图和开发包位于忽略目录 `.work/backup-restore/`。主机测试使用私有临时数据；不自动对用户设备执行真正的数据还原。
