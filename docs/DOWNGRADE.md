# 版本回退与启动失败恢复

开发分支为 dev。本功能首批实现于 0.3.3，不修改普通在线更新源。
0.3.4 按用户授权单独交付至降级目录，验收、包身份与发布记录见

当前页面用语统一为“版本回退”；启动失败时提示“如果上一个版本可用，可以进行版本回退”。
正常使用时也可从“设置 → 软件更新 → 版本回退”进入。先显示旧版本可能与现有聊天数据不兼容、导致数据丢失的警告，点击“继续”后复用同一独立页面。内部rescue/downgrade接口、服务器路径和已有备份目录保持不变。

## 独立启动边界

每个完整 AMR 同时带有 `libs/arm/libjsapi_penchat_rescue_<hash>.so` 和
`libs/arm64/libjsapi_penchat_rescue_<hash>.so`。Falcon PMS 按宿主 ABI／SKU 规则选择
一个目录，并把选中的 SO 解压到安装目录的 libs 根目录。包内不再放自动加载的根目录
主 launcher，也不放会遮蔽标准 ABI 目录的自定义 SKU launcher。

`penchatRescue` 先读取设备树与 Falcon cfg.json，识别实际 RK3562／CV1826 硬件族、
宿主位数及逻辑屏幕，再检查包目标和主程序 ELF。屏幕尺寸没有机型兜底，也不按分辨率
猜测平台。S6 沿用 Falcon 物理屏幕旋转后的逻辑尺寸；Y07 的显式圆角能力复用
ScreenSafety。失败页由 Falcon 控件绘制，可滚动，不依赖原生显示面、字体或数据库。

普通主运行时位于 `assets/runtime/libpenchat_runtime_<hash>.so`，只有环境兼容、
路径／SHA-256／ELF 检查通过后才 dlopen，通过 `penchat_create_runtime_v1` 创建原有
launcher。原生程序、扫描器及硬件资源继续只含本包目标架构；双架构例外只适用于两份
降级 SO。降级库不链接 LVGL、字体、拼音、MicroTeX、扫描器或媒体／NPU 库。
它只使用 SDK、源锁定 curl/miniz、系统 OpenSSL/zlib 和基础 C/C++ 运行库。
SQLite 使用可选只读 dlopen，失败按数据兼容性未知处理，不阻断其他功能。

支持前提是 Falcon 宿主及本宿主 ABI 的降级 SO 本体能够加载。Falcon 本身损坏、
两个降级库缺失或系统基础依赖损坏不在应用内恢复范围。低版本覆盖额外按已核验的 Falcon PMS 固件指纹启用；未知固件不猜测私有覆盖参数，保留备份并提示可选同版本匹配包。

## 下载、备份及安装

实际硬件决定版本源，不允许用户选另一个硬件族：

- RK：`https://cdn.ls-jl.cn/app/downgrade/penchat-rk3562/`
- CVI：`https://cdn.ls-jl.cn/app/downgrade/penchat-cv1826-s/`

版本子目录包含完整 AMR、`<AMR>.sha256` 和最后发布的 `release.json`。
format=1 元数据包含 version、platform、appid、file、size、sha256、build、channel、
schema.min/max、known_issues，以及可选release_notes和install_warning。列表按语义版本倒序，校验元数据、校验文件及 AMR HEAD
长度，未完成发布的版本不展示。允许同版重装及旧版选择。下载使用有界流式缓冲、
取消、进度、TLS 校验和固定来源；不跟随重定向，不调用 shell。

安装前验证 SHA-256、大小、AMR 全路径／重复条目／CRC、AppID、版本、解压空间及
所有 ELF 的实际架构。只有标准 arm／arm64 降级 SO 可以跨架构共存。未知或不兼容
schema 必须由用户点击“备份并强制降级”；强制只放宽数据兼容性，完整性、身份、ABI、
TLS 或空间检查仍然生效，不清空数据、不做逆向迁移。

停止并确认本应用原生进程退出后，后台备份整个私有 data 和
`/userdisk/Favorite/PenChat`，包括 DB/WAL/SHM、资产、设置、IME、公共导入导出文件及
空目录。拒绝符号链接和特殊文件，不读其他应用或修改系统相册。备份排除自身 `.rescue`
和下载临时文件，以流式复制、逐文件 SHA、清单及文件／目录 fsync 保证落盘。
备份位于 `data/.rescue/backups/<operation UUID>/`；失败、文件变化或空间不足均不安装。
原生降级交接停止保留公共导出文件，正常用户退出仍遵循原来的导出持久化设置。

安装票据持久化后才调用 Falcon 包管理接口，不卸载、不清数据、不重启宿主。
RK 的已核验 PMS 使用 0x4000 允许低版本覆盖，该位在 AMR 校验及 ABI 处理之后才跳过版本比较，不跳过完整性检查；已核验 CVI PMS 用原 flags=0 即允许旧版本。四台固件指纹见源码 installationFlags，原始接口证据在忽略目录 firmware。该版本覆盖许可与“强制降级”的数据兼容性确认分开。

每个 operation 只提交一次；超时是待确认，不能当作取消或自动重试。实际安装确认
同时核对本 AppID、版本、安装目录、ELF 和主程序 SHA，不能只看版本号判定同版修复成功。
已提交安装的完成回调只持有自己的持久化路径与操作身份，不持有可能已释放的页面／
Service 指针。确认后重新打开应用。历史包可能没有这个降级入口，以历史版本自身为准。

## 自动精简诊断

失败后自动使用独立后台队列，复用私有构建反馈配置的 HTTPS 协议和节点。
记录版本、实际平台／ABI、包目标、Falcon 屏幕、白名单失败分类、数值退出状态及最多
24 条白名单数值诊断摘要。不上传聊天、草稿、图片、Provider 配置、密钥、数据库或原始日志；
不会为诊断打开采集设备或按键。测试报告可携带独立的 test_run UUID，生产包不设此字段。

报告 ID 和指纹收据持久化到 `.rescue/reports/`，同版本／组件／故障指纹 24 小时去重。
最多保留 32 份有界收据，临时错误最多四次尝试，退避为 10／30／120 秒，重启继续待发送
报告；手动重试复用同一 ID。上传不阻塞版本列表、下载或备份。控制中心／熄屏的页面隐藏
不停止网络任务；明确离开降级取消未提交作业，已提交票据只能核对结果。
