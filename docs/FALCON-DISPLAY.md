# Falcon 显示配置（0.1.34）

设备配置路径：`/etc/miniapp/resources/cfg.json`，使用根对象的 `screen` 段。

- `width/height`：逻辑显示范围，必须显式存在且为有效整数。缺失、不可读或非法时明确报错，不提供固定分辨率回退。
- `direction`、`xoffset/yoffset`：原生 DRM 显示旋转和偏移；缺省为零。
- `tp_direction`、`tp_xoffset/tp_yoffset`：由 Falcon 应用到触摸。应用不再旋转或缩放一次。

原生进程启动读取一次，LVGL、缓冲区和 DRM 使用同一份配置。
`booted.screen` 将尺寸通知薄启动器，启动器据此发送全屏 `display.area`，hole 与触摸覆盖层使用完整视口。
聊天输入胶囊、回底、新建提示、选择面板、固定页头操作、相机/裁剪/扫描预览，以及键盘左右分区均按实际可用区域排布。
字体、44px 触摸目标、间距与可读面板最大宽度为设计尺寸，不是另一套虚拟屏幕。

内置键盘统一使用 `EditorLayout`；正文、候选、剪贴板、拖柄、放大镜及触摸命中共享计算结果。
主机离屏运行也必须显式传 `--screen-config <JSON文件>`，没有隐式主机分辨率。
相机的采集模式是传感器帧尺寸，与屏幕配置无关，不用屏幕分辨率替代。

## 验证

- 主机实际进程：960×266、936×280、1024×320 三种配置；启动通知、显示区域、键盘全键位边界、模式切换、剪贴板、官方取消恢复及设置页通过。
- 非法/缺失配置与超范围整数拒绝；缺失配置时不会创建业务数据库。
- 完整 `npm test` 通过，ORANGE Markdown 像素基线保持一致；配置/编辑器流程 ASAN、UBSan、泄漏检查通过。
- AArch64 与生产 AMR 身份、依赖、strip 和资源校验通过。`npm run check` 仅报告原有可选 cnpm 建议。
- Y02 `MEA2300009007113`：配置为936×280、旋转270°、零偏移。
- ORANGE `MEB0400008900794`：配置为960×266、旋转270°、显示y偏移107、触摸x偏移113。
- 两台设备均通过四角真实触摸、聊天/抽屉/设置截图、字母/数字/符号/拼音候选、官方键盘取消保留输入、前后台显示层释放恢复；原数据与公共目录逐文件校验恢复，宿主PID不变。

真机用例显式指定序列号，读取实际配置并发现触摸事件设备。设备须保持唤醒；等待 Falcon 入场动画结束后再验证坐标，不能将动画中的临时坐标变化当作需要二次缩放的依据。
截图保存在忽略的 `.work/device-display-<serial>/`；不将设备数据或截图提交 Git。
扫描仍只启用已校准的 ORANGE 硬件 profile，Y02 显示/输入通过不代表扫描采集已适配。
