# S6 / CV1826 适配记录

开发分支 `s6-armv7` 从 `dev` 的 `40378a3` 创建，使用独立工作树，不携入
另一个工作树尚未提交的 Y07 修改。普通开发不升版本、不发布、不推送。

## 已验证的模型基线

复用用户提供的 `cv1826_int8_complete_20261018` 已验收资料包，原件保持不变。
使用其中已实测的 INT8 模型，不重新转换；模型、runtime 参考、接口说明及人工
验收记录的大小和 SHA-256 固定在 `native/scanner/cvi-dependencies.lock.json`。
`python3 scripts/prepare-scanner-cvi.py` 检查来源；可用 `--stage` 指定生成目录。
不会复制系统 runtime 或研究数据到仓库/安装包。

原交付已验证 CVI 设备推理与桌面拼接。接入 PenChat 后仍须独立验证完整
ARM32 采集、选帧、CPU 拼接与 UI，不把旧验收扩大为整个应用已适配。

## CVI 后端

`makeCvi32` 实现现有 `Inference` 接口，只调用公开的 `CVI_NN_*` API。
输入为 NCHW `[32,3,144,80]` FP32；灰度复制至 RGB 并按原均值/标准差归一化，
尾帧使用 `[124,116,104]` 填充。直接填入 runtime 输入，避免第二份 4.22MiB
应用中转。九路输出按名称匹配，校验维度、类型、大小与模型目标/版本。
原有 32/24/8 窗口、光照与几何解码保持不变。

本地动态 runtime 测试覆盖 1～32 尾批、三个通道与所有像素的精确填充、输出
顺序变化、错误型号/重复输出/错误输入、推理失败和重复关闭/重新打开。

2026-11-07 在 S6 `JDA0700006552216` 上执行新后端的 ARM32 诊断程序，
将交付包首窗灰度输入送入原设备 runtime：九路输出与交付 INT8 参考均逐字节
一致。ION 使用量执行前后均为 71,356,416 字节。该测试不修改系统组件、
不重启宿主、不访问聊天数据，也没有进行实际扫描。

`scanner-cvi-replay` 是显式构建的诊断入口，读取固定32帧80×144灰度并输出
九个头，不进入生产包。运行参数为：模型、runtime、灰度文件、输出前缀。

## 设备差异与待验收范围

S6 是 Cvitek CV1826 / Plum V0，ARMv7 hard-float、glibc2.23；不能运行 AArch64
二进制或 RKNN 模型。Falcon 配置的面板为260×640、旋转270度；逻辑坐标须
从配置和平台显示语义计算，不沿用 Falcon 错误的800×480环境值或写死分辨率。
原生显示通过独立 CVI VO 与 Falcon `<hole>` 合成，不写 framebuffer。
逻辑画布640×260来自本机配置的物理260×640及270°旋转，其他尺寸同样计算。
键盘复用同一状态机和控件，以原设计画布整体变换，手动命中坐标做相反变换。

本机 sensor_cfg 指向 PIXART PAG7920 240P 100FPS，CVI 视频节点不同于
Rockchip V4L2 自路；原帧采集和资源借用须独立接入。按键/灯读取本机 Plum
配置并按设备身份发现，不能套用 ORANGE 的节点、GPIO或校准。

仅操作本任务 S6；Y02/113 禁止访问，Y07 留给原工作树任务。

## 目标隔离与构建

- `bash scripts/build-lvgl.sh s6`：ARMv7 hard-float / GCC6 / glibc2.23，源码构建
  LVGL、渲染和网络依赖，输出到 `build/s6`、`build/payload-s6`。
- 设置 `PENCHAT_S6_OPENCV_ARCHIVE` 指向锁定的 OpenCV3.4.3 源码归档后，执行
  `bash scripts/build-scanner-s6.sh`。扫描 C++17 使用 clang18 与 GCC6 sysroot；
  OpenCV core/imgproc 从源码静态构建。ARM32 PNG/zlib 来自本机并校验摘要。
  `PENCHAT_S6_PNG_INCLUDE` 可指定锁定 PNG 头文件目录。
- `python3 scripts/package-s6-dev.py` 先增量编译必要目标，再独立暂存和打包。
  `--ui-only` 只用于隔离显示调试，包内不带扫描入口所需产物，不能作为扫描交付。
- ARM32 目标与现有 AArch64 的源码、组件一致，依赖缓存、构建和暂存目录独立。
  `tests/check_s6_amr.py` 检查相同身份、版本、所有 ELF 的 ARM32 hard-float、
  模型校验值，并拒绝 AArch64、RKNN模型、研究文件及设备专有媒体库混入。
- `libpenchat_cvi_media.so` 是源码构建的依赖组合，只引用设备已有 SDK 以解决
  旧库的数据符号循环；不加载原厂相机封装或拼接引擎，不分发其系统库。
- S6 构建不使用 Rockchip 更新源；独立拍照设备未发现，拍照入口明确提示不支持。

## 本机驱动与 SDK 生命周期

2026-11-08 定位并修复的三个独立问题：

1. **整页偏上**：cvifb 实际 `start_x=110`，Falcon 的宽高不包含这个视频层物理
   起点。CVI 后端读取 `/sys/module/cvifb/parameters/start_x` / `start_y` 并对齐
   图层，不写死110、不借触摸偏移补画面。设备读回 COMPOSE 为110,0,260,640。
2. **采集切换触发内核异常**：旧驱动在另一个进程关闭视频设备时可能释放共享
   控制对象。释放显示图层不足以完成移交：必须等待 VO 线程退出、解除其设备
   映射并关闭自己的显示描述符，再允许 CaptureFrame 切换。SDK系统上下文只
   初始化一次，不重复执行广泛的 SYS suspend/resume，也不改系统库或时序。
3. **显示重建触发用户态崩溃**：libsys 的 IonFree 最后一条记录会释放 hashmap，
   但保留 ION fd；后续 IonAlloc 跳过建表，在 hashmapPut（相对地址0x590e）
   解引用空表。通过公开 API 保留一块4KiB进程期 anchor，退出后释放；不修改
   私有数据。回归覆盖20次模拟分配/释放，ASAN/UBSan通过；S6连续10次显示
   重建保持同一进程。

扫描 SDK 的 VI 输出必须在 VPSS 消费通道就绪后启用；此前相反顺序初始化成功
却无帧。根据原厂运行状态核对10bit pipe及 ISP tuning 后，独立诊断3秒连续取得
约292～296帧。IR开启后确认非零320×240有效像素，退出恢复灯值与原厂采集。
原帧图是笔头当前静止视野，不能据此宣称纸面拼接画质验收成功。

S6 父进程在确认采集租约前原子保存私有恢复记录，异常退出后下次启动在打开
显示前按原 PID＋启动时间恢复 guardian；持有扫描进程锁，拒绝与在用任务竞争。
正常释放后移除记录。不得通过重启系统宿主解决资源问题。

### 实体显示验收未完成（更新）

用户随后反馈完整包和仅界面包均可能黑屏、偶尔闪现；因此上述进程存活、
`ready` 和 LVGL 截图只证明软件状态，**不能视为实体显示成功或适配完成**。
已暂停实际划扫，设备临时使用仅界面测试包；这时笔头按键归系统所有，进入
原版扫描页是此隔离包的预期行为。

只读核对：宿主持有 `/dev/fb0`，PenChat 使用 `/dev/video109`，没有向fb0
写像素；cvifb 的 pan 路径更新 GOP，而原生走视频层，共享显示硬件。当前
framebuffer 显示页 Alpha 全为0，透明窗口有效。送帧/出队 ioctl 已收到成功
返回，但这仍不能替代实体屏幕观察。

“补三帧启动队列”的试验没有通过用户验收，已撤回。已校正恒零的帧时间戳，
并改为开流前在自己的既有fd上显式协商/验证 NV12 输入；不再接受共享SDK
缓存看似正确但实际G_FMT宽高为0的状态。最新实体结果待确认，不能发布。
