# S6 / CV1826 适配记录

开发分支 `s6-armv7` 从 `dev` 的 `40378a3` 创建，使用独立工作树，不携入
另一个工作树尚未提交的 Y07 修改。普通开发不升版本、不发布、不推送。

## 已验证的模型基线

复用用户提供的 `cv1826_int8_complete_20261018` 已验收资料包，原件保持不变。
使用其中已实测的 INT8 模型，不重新转换；模型、runtime 参考、接口说明及人工
验收记录的大小和 SHA-256 固定在 `native/scanner/cvi-dependencies.lock.json`。
`python3 scripts/prepare-scanner-cvi.py` 检查来源；可用 `--stage` 指定生成目录。
不会复制系统 runtime 或研究数据到仓库/安装包。

原交付已验证 CVI 设备推理与桌面拼接。接入 PenChat 后仍须独立验证完整
ARM32 采集、选帧、CPU 拼接与 UI，不把旧验收扩大为整个应用已适配。

## CVI 后端

`makeCvi32` 实现现有 `Inference` 接口，只调用公开的 `CVI_NN_*` API。
输入为 NCHW `[32,3,144,80]` FP32；灰度复制至 RGB 并按原均值/标准差归一化，
尾帧使用 `[124,116,104]` 填充。直接填入 runtime 输入，避免第二份 4.22MiB
应用中转。九路输出按名称匹配，校验维度、类型、大小与模型目标/版本。
原有 32/24/8 窗口、光照与几何解码保持不变。

本地动态 runtime 测试覆盖 1～32 尾批、三个通道与所有像素的精确填充、输出
顺序变化、错误型号/重复输出/错误输入、推理失败和重复关闭/重新打开。

2026-11-07 在 S6 `JDA0700006552216` 上执行新后端的 ARM32 诊断程序，
将交付包首窗灰度输入送入原设备 runtime：九路输出与交付 INT8 参考均逐字节
一致。ION 使用量执行前后均为 71,356,416 字节。该测试不修改系统组件、
不重启宿主、不访问聊天数据，也没有进行实际扫描。

`scanner-cvi-replay` 是显式构建的诊断入口，读取固定32帧80×144灰度并输出
九个头，不进入生产包。运行参数为：模型、runtime、灰度文件、输出前缀。

## 设备差异与待验收范围

S6 是 Cvitek CV1826 / Plum V0，ARMv7 hard-float、glibc2.23；不能运行 AArch64
二进制或 RKNN 模型。Falcon 配置的面板为260×640、旋转270度；逻辑坐标须
从配置和平台显示语义计算，不沿用 Falcon 错误的800×480环境值或写死分辨率。
原生显示需要 CVI VO，不可写 framebuffer 夺取系统画面；已有 `<hole>` 显示
实验可作接入参考。尚未完成应用显示与布局验收。

本机 sensor_cfg 指向 PIXART PAG7920 240P 100FPS，CVI 视频节点不同于
Rockchip V4L2 自路；原帧采集和资源借用须独立接入。按键/灯读取本机 Plum
配置并按设备身份发现，不能套用 ORANGE 的节点、GPIO或校准。

仅操作本任务 S6；Y02/113 禁止访问，Y07 留给原工作树任务。
