### 已确认的问题

1. **错误分类和原因丢失。**
   `poll()` 将接收、消息格式检查、屏幕握手和各事件处理置于同一层
   `try/catch`，捕获异常后统一显示“原生页面通信失败”，没有保留具体阶段
   和原始异常类别。这个提示来自启动器，不是模型 API 的网络错误提示。
2. **局部功能故障会扩大为整页故障。**
   `startOcr()` 中的 `new globalModule.Global()` 等初始化步骤缺少局部
   异常保护。管理器构造失败会冒泡到 `poll()`，再经 `fail()` 调用
   `launcher.stop()`，停止原生进程。此路径已模拟复现，**不代表该用户
   实际遇到的就是 OCR 故障**。
3. **错误页面保留，重新进入不一定重新启动。**
   `fail()` 设置 `running=false` 并保留 `errorText`；`resume()` 只在
   没有错误文字时调用 `boot()`。一次短暂异常消失后，再回到页面仍会
   停在错误提示，需要点击“重新启动”。因此“一直显示”不等于持续重复故障。
