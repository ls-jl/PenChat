# 0.2.12：连接复用与空闲保留

## 使用

设置中的“连接保留时间”接受15～600的整数秒数，默认90秒，支持恢复默认。
设置保存在现有应用设置 `http_idle_seconds`，无数据库迁移；无效旧值按90秒读取。
说明为“请求结束后计时，服务器可能提前断开”。调整时长立即重算已有空闲分区的期限，
不取消正在执行的请求。后台和官方键盘不会关闭缓存，原生进程退出会释放全部连接。

## 实现边界

`http_service.cpp` 的单一网络线程持有持久 CURLM，原有 `http`/`apiRequest` 同步接口
供后台任务使用，LVGL 不等待网络。聊天、重试、命名、压缩及模型列表使用同一入口。
最多4个未发布结果的请求、8个排队请求、8个缓存分区和8条实际连接；已发布结果的
短暂 HTTP 收尾计入连接上限。排队满返回明确错误，不自动提交第二次请求。

每个分区使用同线程 CURLSH 管理连接、DNS和TLS会话缓存，按 Provider、API端点、
凭据代次、请求头配置和HTTP版本隔离。缓存键只在内存存在，不输出到诊断。
Provider 保存后旧分区退役；已有请求继续使用原快照。空闲分区按最近使用时间回收，
最后一个 HTTP 请求结束后开始计时。线程主动检查到期，不依赖下一次请求触发清理。

协议结束与HTTP结束分别处理。Chat 的 `finish_reason` 不会吞掉后续用量块；
明确协议结束后立即交付业务结果并清除调用者指针和回调，网络线程最多再收尾1秒或
64KiB。正常HTTP结束才缓存连接；取消、断流或超限则关闭，已经完成的回复保持成功。
下一次请求无需等旧请求收尾。保留TLS证书及主机名验证，不发送心跳，不跨站跟随重定向。

`HttpResult.timings` 包含DNS、TCP、TLS、首字节、排队和总耗时、是否复用及新连接数；
流式消息单独记录 `first_body_ms`。诊断不记录认证头、缓存键、正文或加密思考内容。

实现依据：[CURLSH共享范围](https://curl.se/libcurl/c/CURLSHOPT_SHARE.html)、
[请求前回调](https://curl.se/libcurl/c/CURLOPT_PREREQFUNCTION.html)、
[空闲连接年龄](https://curl.se/libcurl/c/CURLOPT_MAXAGE_CONN.html)。

## 构建

设备自带libcurl 7.79.1缺少请求前回调，无法可靠阻止内部重发。本项目从锁定源码静态
构建libcurl 8.17.0，使用设备现有OpenSSL 1.1和zlib，不修改系统库。8.18起要求
OpenSSL 3，因此当前设备采用8.17兼容线。OpenSSL 1.1.1w仅提供构建头文件，
不打包另一份OpenSSL。来源与校验见依赖锁，许可见第三方声明。

`build-http-deps.sh` 构建host或orange静态库。设备系统库首次准备只读拉取至忽略目录，
可用 `PENCHAT_ADB_SERIAL` 指定验收设备。生产包不依赖设备libcurl、不含测试CA入口。
测试探针和回环服务器单独构建，不进入AMR。

## 验证

`test_http_pool.py` 使用本地临时受信证书验证冷/热TLS、默认90及15/600边界、动态修改、
主动到期、服务器断开、凭据隔离、三种协议、尾部用量、挂起/超大尾部、取消、队列限制、
退出清理和一次提交。另验证不受信证书被拒绝。`test_http_settings.py` 在两种布局下
验证输入、恢复默认、持久化、返回位置和后台行为。真实公网站点未用于付费联调。

设备入口：`python3 tests/device/display_config.py --serial <指定序列号> --http-pool`。
使用隔离假数据，测试后恢复私有及公共目录，核对宿主PID。设备无网络也可使用
源码构建的本机回环TLS服务；临时证书只交给测试探针，生产程序没有CA覆盖入口。

2026-10-28～29 ORANGE本机测试：冷连接TLS约16.47ms、首字节59.09ms，复用后TLS 0ms、
首字节0.47ms。已验证三种协议、15秒主动到期、后台/官方键盘保留、15/600设置与重启、
退出无残留连接；用户数据恢复、宿主PID不变。这是本地测试数据，不代表真实弱网收益。
