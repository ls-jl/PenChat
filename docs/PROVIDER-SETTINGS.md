# 服务商连接与模型管理

此开发变更位于 `model-provider-settings` 独立分支，不改应用版本和数据库结构。

## 用户操作

- **添加服务商**：填写名称、服务地址、API Key、接口类型并保存。允许暂时没有模型；保存后进入添加模型页面，也可返回以后再添加。
- **连接设置**：随时修改 Base URL、密钥、接口类型及高级选项。保存只更新原服务商记录，不改模型列表、模型能力或已选模型。
- **添加模型**：先获取列表、筛选并勾选，或手动填写多个 ID。获取结果不会自动入库，已有模型标记“已添加”。点击“添加选中”才新增，保留其他模型和当前默认值。没有可用模型时初始化默认模型。点击已添加的模型名称才会切换当前聊天，并更新新聊天默认。
- **编辑模型**：模型 ID 是实际请求参数；显示名称用于模型列表、选择器与预设摘要，不改变请求参数。与推理、图片能力、上下文等设置一起明确保存。保留内部模型 ID、Provider 归属及历史关联。同一服务商不允许重复的模型 ID。
- **删除模型**：确认后从可用列表移除，保留历史及软引用。已有会话或预设引用失效时，沿用重新选择的提示。再次添加相同模型 ID 可恢复原内部记录、显示名称和能力设置，不复制一份。

高级连接选项默认收起，包括 Provider 默认强度、API 兼容设置、厂商参数适配，以及 Messages 的鉴权、版本、请求头和新模型输出额度。修改连接和模型能力都不会自动发起聊天请求。

## 布局

继续由 Falcon 逻辑几何判断布局类型。短横屏和竖屏的连接、模型、兼容与 Messages 表单采用共享单列排布，长横屏保留适用的双列。短横屏把模型参数映射入口放入正文，不和保存、标题争用页头。标题与操作随阅读区滚动。

模型结果每页最多30项，关键词筛选不清除选择。手动模型和已选项在异步刷新后保留；退出页面或切换服务商使旧请求结果失效。列表请求与原有三个 API 的 HTTP 设置及 Provider／凭据分区共用，不新增协议或自动重试。仅新增模型、改名称或默认强度时保留连接池，连接信息变化才使旧池失效。

## 存储接口

`saveProvider(form, names, replaceModels)` 保留旧完整列表保存语义作为默认参数，以兼容已有内部调用；连接页显式使用 `replaceModels=false` 与空模型列表。`addProviderModels` 在数据库工作线程读取最新 Provider 并进行增量添加。单模型名称、显示名和能力通过同一 UPDATE 保存。删除软停用及默认模型调整在同一事务中执行。

Messages 的新模型输出额度保存到 Provider 元数据，只用于之后新增的模型，不覆盖已有模型额度。密钥不进入模型列表、截图夹具、能力配置或诊断定位信息。

## 定向检查

```sh
cmake --build build/host --target penchat-lvgl penchat-provider-settings-tests -j2
ctest --test-dir build/host -R '^penchat-provider-settings$' --output-on-failure
python3 tests/test_provider_settings_ui.py
```

检查使用隔离数据库和本地假服务，不使用真实 API Key，不连接设备或调用付费模型。界面截图放在 Git 忽略的 `.work/providers/`。本轮不自动运行全套发布检查、不改版本、不推送，也不向其他会话的 dev 工作目录写入代码或构建文件。

### 本轮检查结果

- 原生仓储定向用例通过：无模型服务商、连接更新不改模型、增量添加、同 ID 去重、模型改名与历史关联、删除默认模型、同 ID 恢复、重复 ID 拒绝、失败事务回滚及 Messages 新模型输出额度。
- 实际 LVGL 流程覆盖640×360、400×240、960×266、568×1210四组逻辑几何；截图检查服务商列表、连接表单、模型勾选／筛选、模型编辑、删除确认、协议选择与 Messages 连接设置。最终短横屏布局又做了一次流程复检。
- 原有 API 兼容设置、模型能力填充与重启恢复用例通过；Messages 设置中的鉴权、版本、自定义头、输出预算和能力编辑通过。
- 本地 HTTP/1.1 服务验证模型列表请求使用 Provider／凭据连接分区，新增模型前后的请求复用同一条 TCP 连接。
- 只使用本地假服务与隔离数据。未进行设备操作、真实模型联调、跨架构打包或全套 Release 检查。
