# 服务商连接与模型管理

模型管理首页只列出 Provider；点击整行进入同一页中的连接配置和模型列表。本功能位于 `dev`，不改变版本和数据库结构。

## 一页配置，统一保存

- 上方填写名称、Base URL、API Key、接口类型及高级连接选项，下方管理本 Provider 的模型。长横屏连接表单适用双列，竖屏、短横屏使用单列；模型区独立排布。
- 页头和模型列表末尾的“保存”执行同一个事务。新 Provider 未保存时也能添加、编辑模型，不要求先保存连接。
- “获取模型列表”使用当前页面的地址、Key、协议和连接选项。只获取候选，不写数据库、不调用聊天模型。手动填写、筛选和每页30条的候选列表继续可用。
- “加入草稿”只暂存选中模型；参数页“完成”只更新模型草稿，返回取消本次参数修改。回到详情页保留连接草稿和阅读位置。
- 删除先标记“待删除”，点击回转箭头可以撤销；整页保存后才软停用。删除新加但未保存的模型不会创建数据库记录。
- 未保存时返回列表，提供“继续编辑／放弃修改／保存并返回”悬浮菜单。保存失败保留全部草稿，成功后仍停留在本 Provider 详情页。
- 模型管理中没有“使用／设为默认”入口或单选标记。模型使用由会话预设与聊天中的选择决定；配置模型不切换当前聊天。

模型 ID、显示名称、能力及手工覆盖保持分离。只有新模型且用户未修改能力时，切换草稿协议才重新初始化其推荐值；已经保存的模型和用户修改过的能力不被批量改写。Messages 输出额度及思考预算继续校验。

## 数据与生命周期

仓储内部 `saveProviderWorkspace(form, models)` 将 Provider、模型新增、参数修改和软删除作为单一 DB 工作线程事务提交；失败全部回滚。现有 Provider/模型 ID 及历史引用保持稳定，同 Provider 重复 ID 拒绝保存；恢复已停用模型继续使用原记录。

旧 `saveProvider` 允许参与外层事务，连接池只在最终提交成功且连接身份确实变化后失效。模型能力、协议、密钥与请求参数的发送时快照规则保持不变。现有默认记录仅作旧数据和未指定选择的兼容处理，不向管理页新增默认模型设置。

草稿仅在进程内，字段、候选及模型编辑页共用一个工作区；退出工作区/进程时释放。模型获取结果同时校验工作区、请求代次和连接草稿，取消或过期结果不得回写。草稿不进日志、导出包或诊断；诊断只提供工作区状态及公开模型定位信息，不含凭据。

## 定向检查

- `penchat-provider-settings-tests`：保留现有增量管理用例，增加整页事务、稳定 ID、删除/恢复、重复与所有权校验、注入写入失败回滚及新 Provider 同时创建模型。
- `python3 tests/test_provider_settings_ui.py`：三类布局中的 Provider-only 首页、未保存连接获取、参数完成/取消、删除撤销、统一保存、错误保留、离页选择、软恢复和新 Provider 先加模型。
- UI 用例仅使用主机虚构凭据与本地 HTTP 服务；截图位于忽略的 `.work/providers/`。不据此声称真实 API 联调或全套发布验收通过。
