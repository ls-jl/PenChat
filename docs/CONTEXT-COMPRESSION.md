# 上下文压缩（自 0.1.23 起）

设置中的“自动上下文压缩”默认开启；加号菜单可手动“压缩上下文”或“查看上下文摘要”。
摘要生效后，聊天左侧的历史图标也可打开详情，查看覆盖终点、生成时间及对应的“压缩前副本”。
原消息、公开思考和原图仍然保留在当前会话中。此功能不减少本地聊天记录占用。

## 模型和预算

模型编辑页可设置“上下文预算（本地估算 token）”，默认 16,384，范围 1,024～2,097,152。
它是保守的本地调度预算，不是接口精确计费数量或模型厂商声明的上下文窗口。
估算使用每三个 ASCII 字符一个 token、每个其他 Unicode 码点两个 token、每条消息 16 个
封装 token，以及每张图片 2,048 个 token。图片的 Base64 不作为普通文字计算。
对尚未覆盖的 Responses 不透明思考条目另预留每项 1,024 token；该估算不是精确的推理消耗。

发送前达到预算 75% 时先压缩，目标是摘要、剩余历史、系统提示词和本次输入合计不超过 50%。
优先保留最近四轮；若它们本身超出目标则扩大前缀范围。只在助手消息末尾切分覆盖范围，
待发送文字和最后一轮之后的待发送图片均不压缩。手动压缩可处理更短的历史。
没有可处理的助手回复时不发起摘要请求。

预设编辑中的“上下文压缩模型”默认为“跟随聊天模型”；选择另一预设时，留空会明确清除
上一预设指定的压缩模型。上拉新建继承该选择，历史菜单新建应用默认预设。
摘要及其覆盖范围属于原会话，不随新建复制。切换模型/预设不使既有有效摘要失效。

## 请求与失败

摘要请求使用现有 Responses 或 Chat Completions，API 默认推理强度，不请求公开思考。
整理指令只用于这次辅助请求；原会话提示词不用于整理历史。历史内容与已有摘要作为引用数据，
要求保留事实、约束、决定、未解决问题、失败/未完成状态及图片信息，不执行其中指令。
小预算模型按顺序分段，每段携带上一段摘要；整个操作只生成一份归档。

后续聊天把摘要作为普通用户角色的历史参考，之后跟未覆盖原文与本次输入；系统提示词仍只注入一次。
覆盖范围内的原图和加密思考条目不续传，原图保留在本地。模型能力显式声明 `vision:false` 时
拒绝带图片的压缩；未知能力由接口验证，拒绝后不换模型、不自动重试。

请求开始冻结聊天/压缩模型配置、输入及凭据；停止、切换会话、删除源会话或退出使旧结果失效。
压缩失败、摘要过长、模型失效或预算无法满足时，停止排队发送并保留草稿、图片和原上下文。
关闭自动压缩也会发送完整有效历史；超过本地预算则明确报错，不悄悄截断。
历史准备上限为十万条且参与读取的文本/元数据不超过 32MiB；单张图片最大 16MiB，
单次请求（含估算编码图片）最大 64MiB，超过时明确报错。

## 事务与资产

没有数据库结构升级。`chat_sessions.metadata_json.context_compression` 保存版本、摘要、覆盖 `seq`、
来源校验、修订号、时间和归档 ID。校验采用按消息角色、状态、顺序、正文和图片属性计算的
FNV-1a 64 位摘要，用于检测意外变化，不提供文件真实性或抗篡改保证。

先完成全部网络请求，再在 DB 工作线程的一次事务中检查来源、复制完整会话和替换摘要。
消息、分段、资产和流事件均重新生成内部 ID；归档状态为 archived，标题前缀“压缩前副本”。
私有图片文件共享，不重新复制；现有资产引用检查及压缩任务租约防止误回收。
事务失败或来源过期会整体回滚。每次成功都保留一份归档，不自动删除。

归档还原只将该副本恢复到活动列表，不覆盖继续进行的会话。查看对应归档会定位到归档列表，保留当前草稿和阅读位置；归档删除后摘要仍可继续使用。

## 备份兼容

聊天包可携带公开摘要、覆盖范围和压缩模型描述，不包含加密续传条目或凭据。
压缩前副本作为普通归档会话选择导出。预设包可携带独立压缩模型描述，沿用接口地址、类型和
模型名的唯一匹配规则。缺失模型保留为待配置，不自动创建 Provider。
导入预览检查语义覆盖校验；缺失附件或范围不匹配时保留完整历史、停用摘要并提示重新压缩。
导入重新生成 ID、重建图片路径，已验证的校验重新绑定到导入后的记录，不保留无效的旧归档 ID。
