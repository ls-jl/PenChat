## 检查后保留的机制

- 网络仍按100ms合并显示、500ms合并持久化；独立取消标记，不自动重发请求。
- SQLite单工作线程、事务、64条预编译语句和提交确认保持；不切换日志模式或降低同步。
- 图片缓存32MiB/128项、解码队列64项、公式缓存8MiB保持；字形在帧结束后回收，
  不在字形回调中删除仍可能被绘制使用的位图。绘制一帧期间允许临时超过回收水位。
- 拼音队列单线程、最多32项、只保留最新查询；选择有序、会话/版本校验和35ms合并保持。
- 用户词典10,000条/2MiB，损坏文件保留，取消输入不学习；记忆与程序资源、导出隔离。
- 扫描的窗口、光度估计、640帧队列/110MiB磁盘环和硬件归还流程没有改变。
- 导入导出任务、资产GC、相机采样守护仍按原有引用/租约工作；不删除系统相册原图。
- 正常退出清理不等于强杀时可以执行析构。扫描/采样守护通过父EOF归还资源；
  转存与已知编辑临时文件保留启动恢复机制，未识别文件不会为追求“干净”而删除。

## 验证结果

中间无效批次未作为验收依据：一次ASAN退出异常来自构建期间修改公共头文件导致
对象布局不一致；头文件稳定后统一重建主机/ASAN/AArch64目标，退出及GUI检查通过。
另一次旧资源覆盖造成词表对照无效；修复暂存脚本后，所有基准均先核对资源哈希。

### 113同批算法对照

使用AArch64/GCC 6、`-O3`、同一benchmark程序及固定输入；只测引擎热查询，
不含35ms合并窗口、首次加载与屏幕绘制。没有修改设备频率/调度策略。

| 方案 | 26键Top1/Top5（73例） | 26键中位/P95 | 九键Top1/Top5（70例） | 九键中位/P95 | benchmark峰值RSS |
|---|---|---|---|---|---|
| 0.2.6算法＋旧词典 | 35 / 51 | 11.65 / 13.06 ms | 22 / 42 | 18.27 / 23.60 ms | 16,804 KiB |
| 旧算法＋加权词典 | 57 / 60 | 11.78 / 19.04 ms | 53 / 57 | 21.74 / 31.50 ms | 18,016 KiB |
| 新算法＋加权词典 | 70 / 73 | 0.85 / 2.27 ms | 62 / 67 | 3.66 / 7.30 ms | 12,856 KiB |

这批引擎内存峰值约减少3.86MiB，不代表完整GUI的RSS。设备没有锁频，绝对值随DVFS、
前后台和负载变化；此前较慢一批同机对照为26键40.5→3.3ms、九键65.7→14.1ms。
只在同批内比较，不把不同频率批次的绝对值混用。人工评价集不能证明通用准确率或
优于系统输入法；歧义词仍需要用户选择。一元模型不理解语义上下文。
