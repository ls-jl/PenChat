# 模型能力库（0.2.5）

## 使用

新增模型时，手动输入和自动获取的 ID 都使用同一个离线能力库。匹配不改写实际 API
模型名。编辑已有模型不会自动重设配置；各字段右侧的文档/星形图标只填该字段，
保存后生效。填充后仍可修改，以用户最后保存的值为准。长按图标显示用途，点击
“思考模式”可查看命中规则和官方来源。未匹配、歧义或资源损坏时仍可手动配置。

目前可应用的字段是最大上下文、输入模态、最大输入、思考模式、强度和公开总结。
图片能力参与聊天和压缩的检查。音频、视频、文件及工具调用能力只记录，不增加
上传或执行入口。未知值不等于“不支持”，不会生成虚构的强度或 token 上限。

“最大上下文”是用户控制的本地估算基数，不是精确 tokenizer 计费结果。新增已匹配
模型预填窗口，未匹配模型沿用 16,384；旧模型保留原来的本地预算。设置中的
“自动压缩阈值”默认 75%，可设为 10%～95%，所有模型共用。下一次发送前检查包含
待发内容的估算量，达到 `最大上下文×阈值` 才压缩，成功后尽量降至
`最大上下文×min(50%, 阈值×2/3)`。摘要与完整压缩前归档仍原子提交。

最大输出与默认输出不自动填充。Responses/Chat 默认省略输出额度；Messages 的
`max_tokens` 必填，因此添加模型时提供默认 16,384，可改但不可空。编辑 Provider 的
“新模型输出额度”仅影响本次新增的模型，不覆盖已有模型。

## 构建与数据格式

- 原始工作簿不修改、不随包发布。`native/model-catalog/source.json` 保存参与匹配的
  原始行、必要祖先、原始回归样例及工作簿 SHA256；254 条历史发布参考不参与运行。
- `catalog.json` 是人工核验后的维护源，规则 ID 稳定，原始中文字段被转换成结构化
  事实和按协议区分的参数配置。`sources.lock.json` 记录取回的官方网页摘要校验值，
  `normalization.json` 锁定 Unicode 14.0.0 的 ASCII NFKC 投影。
- 构建无网络、无 Excel 依赖；`compile-model-catalog.py` 生成 CBOR、zlib 数据及 C++
  字节数组。头部为 `PCMC`、小端格式版本、解压长度、CRC32。二进制嵌入
  `libpenchat_model_catalog.a` 并链接进程序，不增加运行库或单独可执行插件。
- 数据最多 2MiB 解码、512KiB 压缩，最多 2,048 节点、16 层继承，模型 ID 规范化后
  最多 256 字节。启动时验证头部、长度、校验、节点唯一性和继承环，编译正则一次。
  CRC 用于损坏检测，不声称提供外部文件真实性认证；本版不接受外部能力库加载。
- 全匹配、最高优先级唯一命中、逐字段只向父级补空。无兄弟推断、无编辑距离猜测。
  已知前缀白名单在数据源中。其他 Unicode 字符不能变成受支持 ASCII ID 时直接
  未匹配，不进行形似字符替换。

重新提取表格仅供维护者执行：

```sh
python3 scripts/import-model-workbook.py /path/to/table.xlsx /tmp/source.json
```

人工核对差异后更新维护源、来源和测试，不能把重新提取的结果直接作为审核结果。

## 厂商适配与持久化

Provider 的“厂商参数适配”默认自动，只精确识别已核实的 HTTPS 官方主机名。
任意中转、相似域名、用户信息或其他端口不获得自动信任。中转须手动指定厂商，
且模型匹配厂商与协议配置一致才发送专用字段；“仅标准参数”始终不发这些扩展。
其他官方新域名在未列入白名单前也需手动选择。不会因参数被拒而自动重发或降档。

模型设置保存在已有 `capabilities_json`，`catalog` 记录规则、数据版本与用户覆盖的
字段。普通旧模型不批量改写；每次请求仍冻结模型和 Provider 配置。命名、压缩的
请求明确使用 API 默认思考，不误带手动的厂商思考开关。续传身份包含适配方式，
变更适配不会混用旧的私有思考状态。
